# 状态诊断与来源指纹

本页说明诊断API、请求身份和资源指纹的实际用途。存档合法性与随机语义分别由[保存规格](../../specs/behavior/BEH-SAVE-0001-session-persistence-replay-and-headless.md)和[随机规格](../../specs/behavior/BEH-SIMULATION-0002-randomness.md)定义；不在实现手册另立加载门槛。

## 用途与所有权

| 用途 | 实现与消费者 |
| --- | --- |
| 原版识别与导入溯源 | Importer按EXE／源数据SHA-256、长度和登记身份选择版本并记录来源；客户端不读取源文件 |
| 纹理来源复用 | 按源内容SHA-256、长度及转换版本识别失效，不以修改时间为依据；定向重建不能为保留单元补造指纹，见[内容发布](../client-content.md#导入编译与发布边界) |
| 世界／会话复现 | 显式`WorldDiagnostics`／`SessionDiagnostics`比较权威状态与事件，不计算默认状态SHA-256或给快照增加StateHash |
| 规则与分析随机 | 稳定非密码学混合与SplitMix64，不依赖全世界哈希，不承担完整性认证 |
| 研究样本／实验输出 | 记录离线来源和对照摘要，不参与游戏对象身份、保存校验或正常播放 |

## 诊断API与成本

`AreEqual`只判断语义相等；`Compare`失败时返回首个字段路径及期望／实际值，`ToDiagnosticJson`才显式导出。源生成JSON元数据按字段分块比较，先跳过共享不可变集合与相等记录，不能直接证明相等的块才规范化／序列化；会话复用世界比较，不重复处理共享世界。

诊断捕获权威状态及不持久化的待答／任务步骤，排除本地提交次数`Revision`；无序集合规范化，有序记录保留顺序。`SessionDiagnostics.Compare(GameSession, GameSession)`可比较已发布待答状态，存档捕获仍只接受稳定边界。只读UI检查可直接比较Revision。

Headless `verify`显式比较连续、恢复和命令脚本执行后的完整状态／事件；普通报告不序列化诊断快照，正常加载不生成玩法内容指纹。入口见[Headless](../headless.md)。这项结构选择不作为未经测量的性能结论。

## 请求与任务身份

本地请求ID直接编码类别与会话序号，自动命令／准备查询编码类别、势力及Core序号，各类别互不混用。不哈希载荷、日期或原因，单机身份不承担跨机器认证。

派生任务由Core的`NextTaskIdentity`单调分配，参与事务回滚与保存恢复；命令拒绝占用派生身份类别，恢复校验现存派生任务序号小于水位。待答以类型化状态和步骤比较，不维护交互指纹集合；消息／播放使用既有事件键，不再哈希成GUID。

## 导入与研究工具

一次Importer操作复用已读源字节和来源摘要，不在每个地图编译器重复读哈希同一EXE／剧本。版本识别与独立研究导出仍可各自执行必要样本核验。实现不得为减少哈希而省略未知版本、引用、范围、稳定边界或任务占用校验。
