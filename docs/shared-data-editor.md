# 游戏资料编辑器

本工具用于验证[共享内容分层](../specs/behavior/BEH-CONTENT-0001-shared-scenario-authoring.md)，目前提供爵位、官职、武将、阵形和兵法五个子页，共用一份共享定义草稿；不提供新增阵形、跨包依赖或 Mod 安装管理。

## 使用

标题菜单左下角点击册页与刻笔图标（底部提示“编辑游戏资料”），或从仓库根目录独立运行：

```powershell
godot --path src/San9.Client.Godot -- --shared-data-editor
```

`--content-root <目录>`指定转换内容根；可加`--scenario <ID>`选择用于名称与共享库定位的参考剧本，不会进入该剧本。未指定时使用目录中的首项作为编辑参考，并在窗口标题的悬停提示中显示实际基础／玩家副本路径。独立启动与其他编辑器、世界验证互斥。

打开时读取目录、剧本入口元数据、当前有效共享定义和人物资料，并独立准备共享头像／旗字资源；不读取各剧本世界、消息正文或地图地理，也不执行跨剧本完整校验。点击保存后才读取这些输入并校验，每次保存中同一共享文件只加载、解析一次，发布前另做文件快照核对；不建立跨保存缓存。

顶层按“爵位”“官职”“武将”“阵形”“兵法”排列五个子页，不预建其余空页。子页共用同一`SharedDataEditorWorkspace`，切换时不销毁页面，也不丢弃内存草稿。

阵形子页左侧搜索和选择阵形，右侧保留基础、战斗、兵法与特性、阵位与完整数据四页。常用字段直接编辑，输入数值立即写入内存草稿；优势兵法类别直接勾选。完整数据页可编辑随兵量变化的占地、兵法引用等进阶参数，应用前拒绝未知字段、身份及数量变化。切换阵形、切页或保存会先应用完整数据草稿，解析失败留在原项，不丢弃输入。

阵位图直接绘制当前数据，不依赖原版阵形图片。阵位拖动区固定为3×3，不自动扩展；已有超出范围的阵形保留原数据，暂不支持拖动编辑。拖动现有编号调整左中右位置和前锋／中锋／后卫排位，放到已有阵位上时交换位置；松开鼠标后写入草稿，拖出图外、按Esc或右键取消，切页和窗口失焦也取消拖动。编号对应的成员顺序保持不变，阵位数量和武将上限暂不编辑，完整数据输入同样禁止改变这两项及将阵位移出3×3范围；其余资格和引用由公共内容规则校验。“恢复打开时的值”恢复本次打开时的原值，即使之前已保存，也可恢复后再保存。

官职子页先提供现有官职的带兵量、每旬俸禄、四项任职能力加成、武官／文官类别、所需爵位、太守排序优先级和优先任命标记。可搜索、选择及恢复本次打开时的值；名称与描述直接编辑并保存在官职定义，不新增或删除官职。爵位子页可直接编辑名称、描述、带兵量、所需信望、忠诚加成、位阶、无爵位标记和任官候选偏好；支持搜索、选择和恢复打开时的值，不新增或删除爵位。武将页与新武将编辑器共用“基本资料”“兵法”“特性”分页、头像预览／分页选择、旗字选择及全部人物表单，亲代与血缘保留在基本资料；熟练度、精通和已学兵法按类别同排显示并支持批量设置／清空；修改共享人物基础资料，包含头像、姓名、姓氏、字、列传、能力、性格、义理、野心、相性、出生与登场年份、相对年龄、寿命档、旗字、亲代、血缘、继承／拥立优先级、九类熟练度、精通、已学兵法、连携与单挑特性；所属、位置、现职和当前状态继续归剧本，新武将人物库仍是独立入口。兵法页提供名称、描述、熟练类别、威力／效果参数、间隔、学习门槛、半径、选择资格、设施作用资格、近距门、狙击类别、救俘资格、设施攻击参数及阵形／船型适配；按效果限定威力范围，暂不改变效果类型及战斗表现。爵位、官职、阵形与兵法仍只修改现有对象，不提供新增或删除；阵形与兵法页展示具有目录资料的规则，未列入目录的内部规则在保存时完整保留。

武将页的亲代与血缘复用新武将亲代的人物搜索选择控件，显示姓名与人物ID，支持清空；亲代排除本人，血缘选择家族血缘根人物并允许指向本人，同族人物使用相同引用。目录外的已有引用明确显示不可用，未重新选择时保留原值。

头像引用归`OfficerDefaults.PortraitKey`，可选择或清除；加载时从有效人物资料同步投影消息人物及列表／情报头像角色，不另保存派生副本。资料schema4包含身份分配记录，需用`import-content --rebuild worlds`更新共享人物资料和剧本世界，复用纹理、静态文本及表现资源。

## 武将的新建、复制与删除

武将页支持新建和复制，生成独立的稳定人物身份；复制保留属性及已有亲代、血缘、兵法和头像引用，原有引用不会自动改指向副本。原有武将可编辑属性、可作为复制来源，不能删除或由副本接管身份。原有项以安装内容的基础人物资料识别，不使用人物编号区间或显示名称判定；即使存在玩家副本，也须保留基础文件供身份归属校验。

删除仅支持自建武将，先确认，再检查共享人物的亲代／血缘、规则偏好及关联剧本的初始状态、额外定义与引用覆盖。存在引用时列出具体位置并保留草稿，不级联删除；保存时用当次读取的内容再次核对已删除项，防止检查后新增引用。新建、复制、删除均只修改内存草稿，“保存全部修改”成功后才发布。

`OfficerDefaultsCatalog.NextOfficerId`保存单调递增的身份分配高水位，删除后不复用已分配身份；分配时同时遵守基础目录和玩家副本的身份分配高水位，并避让当前人物、已知关系及剧本中的额外人物身份；玩家副本缺项不会释放基础身份。不把此记录写入游戏存档。恢复已有项使用本次打开时的值，本次新建／复制项恢复创建时的值。

新增定义不会自动加入剧本世界或任何势力；当前新局部署入口仍只读取独立的新武将人物库。此阶段不提供共享武将的剧本部署界面，也不把复制定义解释为替换原人物。

## 文本所有权

阵形、官职、爵位和兵法的`Name`与`Description`直接持有单语言纯文本，描述允许空字符串，与各自数值一同保存在共享定义；剧本特例沿用显式目录覆盖。人物姓名、字与列传正文存放于`OfficerDefaults.Name`、`CourtesyName`和`Biography`，与人物数值在同一资料文件，剧本人物差异可覆盖这些字段。列传保留已有富文本格式，编辑时不增加语言键或语言包。

界面与消息读取当前组合后的定义。运行消息库不再发布原档案中的独立目录名称／描述和人物姓名／字／列传条目，也不保留无调用的转接消息；各剧本`text.json`不重复发布这些正文。人物仍使用既有运行时文本引用，加载时由有效人物资料投影文本目录和姓名组件，不另保存投影副本。源解析及研究导出保留完整档案；完整台词和通用标签不做全局字符串替换。

阵形的阵位／视野投影从当前目录草稿生成，不覆盖刚编辑的名称和描述；恢复按钮同时恢复该阵形规则和文本。

## 保存边界

保存采用完整文件副本，不做字段合并：

```text
shared/definitions.json          基础共享定义，编辑器不改写
shared/definitions.player.json   完整规则与目录玩家副本
shared/officer-defaults.json     基础共享人物资料
shared/officer-defaults.player.json  完整人物玩家副本
```

- “保存全部修改”或`Ctrl+S`先收齐所有子页的待提交输入，再按公共规则校验引用剧本，最后将完整`ScenarioDefinitions`和完整`OfficerDefaultsCatalog`作为同一批发布，任一文件替换失败回滚整批。五个子页同时保存，未编辑的其他目录与规则完整保留；它不是只含修改字段或修改对象的差分。某一子页输入解析失败时定位到该页，某一数据校验失败时不发布任何子页的修改。
- 完整加载、单独世界加载和势力选择均优先读取玩家副本，没有副本时读取基础文件。副本损坏或版本不符明确失败，不静默回退。制作工具继续发布基础文件，不把玩家副本当作原始内容。
- 组合顺序为基础或玩家完整定义 → 剧本显式差异 → 会话输入。剧本已有的私有军事定义覆盖继续生效；已有对局不热更新，重新开局／重新加载内容后使用副本。
- 完整副本不继承基础文件的任何后续更新，包括未在编辑器中改过的规则。重新转换会更新基础文件，保留玩家副本；不推测合并。关闭编辑器后移走玩家副本，后续加载即可恢复基础文件。
- 保存时合并每个引用剧本的共享与私有消息，检查固定爵位、官职、阵形与兵法引用；消息文件同样受发布前快照检查。打开不执行这项检查。
- 阵位与视野同步投影到副本的目录显示资料；改变阵位后清除不适用的烘焙阵位图片引用，使用普通格线。
- 校验失败或替换失败保留已有文件与草稿。打开时读取的有效定义和入口元数据发生外部修改时要求重新打开；共享人物资料同样受打开快照保护；剧本正文、其他引用资料和地理以保存时读取的最新数据为准，发布前核对其校验快照，变化时中止本次保存，不覆盖外部变化。
- 子页的恢复按钮只恢复当前对象，不影响其他对象或其他子页。恢复的是本次打开时的有效值；若打开时已在使用玩家副本，恢复的也是当时的玩家值。关闭未保存窗口可统一保存全部、放弃全部未保存草稿或继续；保存中不能关闭或再次编辑。
- 该文件通过与基础定义同目录、同文件名前缀的命名明确归属，不是通用 Mod 包。本阶段不提供加载顺序、多份玩家配置或旧存档内容版本管理。

## 验证边界

验收目标为完整副本的加载优先级、基础与剧本文件保持不变、剧本私有规则保留、失败不落盘、外部修改保护、打开不依赖世界／地理／消息文件、五页共同保存且恢复互不影响、人物正文投影、消息目录实体引用检查及爵位履历恢复，以及显示投影。自动测试使用公开夹具覆盖上述契约、保存回滚与恢复边界。实际画面和操作体验由用户验收，不将编译或自动测试作为画面验收。
