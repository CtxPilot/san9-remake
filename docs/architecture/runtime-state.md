# 运行时状态、事务与查询所有权

本页描述架构与派生数据生命周期；采用规则从[领域索引](../../specs/behavior/README.md)查找，实现进度只在对应实施计划维护。不会因某条规则出现在架构说明中就宣称完成或重新验收。

## 当前结构

Core持有确定性世界、规则与事务，Application持有会话、控制轮次、用例及表现投影，Content定义可独立创作契约，Importer解释版本格式。Rendering持有地图合成、投影与动作计划，Godot持有输入、节点及显示资源；Core／Application不依赖Godot、源偏移或研究脚本。

内容提供完整支持集合与初始态；`GameSession.Start`复制为独立WorldState，不同会话不共享可写状态。定义与资源完整保留，是否可见／可用由当前世界和查询决定，不能按首屏裁减人物、宝物、建筑或部队定义。

## 世界发布与事务

WorldState是唯一可写领域状态。命令与日期推进在候选事务中执行，最终共用WorldInvariants校验后一次发布新版本；事务中可暂时跨对象不一致，失败不改变稳定世界、随机、版本和快照。初始化同样拒绝重复身份并检查引用。本模型提供单线程原子发布，不提供并发写同步。

WorldSnapshot为按身份排序的不可变记录，旧快照不随后续提交变化；共享只读集合可复用。人物兵法集合只表达去重成员，不保存学习先后。领域不变量在公共层，业务可执行条件留处理器，客户端不以按钮禁用代替终验。

## 会话、时间与保存

GameSession组织用例与控制席位，经SimulationEngine提交类型化命令；即时效果与持续任务保留各自结算时机。结束控制只转换控制游标，领域集合可复用；领域命令和日推进仍经完整事务。

SimulationState持有日历、两个种子、命名流、控制席位、命令水位及持续任务，GameClock的旬／周期标志由日期派生。WorldState独占执行中标记，多个引擎入口也不能重入。人事行程与军事Order各自持有任务状态，不以固定到期人事任务替代逐日行军。

SaveService从稳定边界捕获必要当前状态，恢复构造新会话，不重跑开局或首旬；CommandLogService执行调用方显式提供的输入，不从会话采集历史。保存／读档语义见[保存BEH](../../specs/behavior/BEH-SAVE-0001-session-persistence-replay-and-headless.md)，诊断成本见[状态诊断](../development/state-diagnostics.md)，随机见[随机BEH](../../specs/behavior/BEH-SIMULATION-0002-randomness.md)。

## 只读显示与选择

Application将世界与静态名称／外观定义组合成按世界版本缓存的StrategySnapshot；HUD、地图标注、名单、建筑外观及小地图读取同一已发布视图。Godot的相机、焦点、悬停、命令草稿、模态和播放进度不进入Core世界。

StrategySelection管理命令起点，名单独立持有过滤及滚动；MapWorld发布拾取并接受定位，不反向拥有游戏规则。世界版本变化使旧草稿失效，资源就绪与当前呈现相机共同提交，详见[战略界面](../ui/strategy-ui.md)与[地图运行](../map-import.md)。

## 派生数据与有效能力

人物位置、归属、任务、伤势、官职及宝物持有是权威事实；有效能力、空闲人数、主将、地利、建筑组合及候选均从事实和规则派生。人物／存档不复制有效能力或宝物／官职加成缓存；同一事务中任免、治疗、易主及成长影响后续计算，旧快照仍按自己的状态读取。

OfficerAbilityRules是能力公共入口；宝物各项最大加成与兵法／名马资格分别沿各自发现／禁用规则，不把不同资格合并。部队／据点最终统率及伤害不跨事务缓存，大将维护与公共转换拥有写回，不由查询或显示修复世界。

## 运行时查询与失效

派生索引生命周期默认为一次WorldMutation，首次使用建立，状态变更入口维护或使其失效；不发布中间状态，不保存进快照、普通存档或摘要。

### 查询所有权与复用

| 类别 | 优化项 | 持有的数据与消费者 |
| --- | --- | --- |
| — | 部队／驻地成员索引 | `UnitMembers`、`SettlementMembers`按位置取得当前参与对象，保留俘虏等非在职成员供战后处理；在职战斗查询再通过公共成员入口筛选。统率、计略防守者、单挑、学习、治疗、救援与战后人员处理已接入。 |
| — | 人物任务索引 | `TasksFor`按人物保留任务顺序，`IsBusy`查询任务占用，`IsTraveling`查询存在行程的任务。战斗及相关命令资格查询复用索引，区分忙碌与在途。 |
| — | 宝物持有索引及效果汇总 | `HolderId`仍是唯一归属事实。按持有人取得宝物，按宝物规则集分别缓存四项最大加成、免俘虏马与宝物兵法来源；能力、兵法资格和战败／单挑免俘虏查询复用汇总。 |
| — | 统一战斗成员查询 | `ServingUnitMembers`筛选在职成员，`ServingSettlementMembers`额外排除在途人员；归属、阵位、伤势等用例条件继续由相应规则筛选，保留各调用路径的排序与随机消费顺序。 |

实现集中在[WorldMutation.Queries.cs](../../src/San9.Core/Simulation/WorldMutation.Queries.cs)，由`WorldMutation`的状态变更入口维护，生命周期为一次事务。首次相关查询建立索引；部队／驻军有效统率随后只遍历当地符合条件的成员并取最大值，无符合条件者为0。部队统率沿用原规则排除在途人员，不直接读取主将统率。

| 派生数据 | 输入依赖 | 更新／失效方式 |
| --- | --- | --- |
| 成员索引 | 当前参与人物记录，尤其是部队、驻地与启用状态 | 人物替换更新旧、新位置中的记录；参与对象启停导致活动记录重建时，成员索引按需重建。身份、归属、伤势变化后查询读取新记录。 |
| 人物任务与在途集合 | 当前`Simulation.Tasks`，包括人物引用、行程和任务内容 | 任务集合改变后失效，下次查询重新建立；仅日期、随机状态等其他模拟字段改变不使索引失效。 |
| 宝物持有索引 | 宝物状态、持有人引用及持有人的启用状态 | 宝物替换更新持有集合；活动记录重建时按需重建。 |
| 宝物效果汇总 | 持有集合、宝物发现状态、对应不可变规则集 | 易主使旧、新持有人汇总失效，发现状态改变使当前持有人汇总失效；活动记录重建时清空汇总。发现地域单独改变不影响效果汇总。 |

能力加成与免俘虏马沿用“未禁用”的宝物条件；宝物授予兵法要求“已出土”。不统一这两种条件。个人最终能力、部队最终统率和伤害结果不缓存，伤势、治疗、任免、能力成长、死亡与成员离队即时影响后续查询。官职按ID读取规则，无需额外汇总缓存。




交战关系、地图占用及路线查询各自声明位置、任务、阵形、归属和外交等输入；只改变钱粮或其他无关字段不能无条件重建所有缓存。跨事务复用须另定依赖和版本失效，不能直接延长当前事务缓存寿命。先测真实热点再优化，扫描减少不构成性能或行为等价证据；测量归[旬推进记录](../ai-performance-records.md)。

## Core代码目录

`src/San9.Core`保留`Domain`（领域状态与基础规则）和`Simulation`（规则执行与世界变更）两层，层内按业务职责分组。子目录用于导航，命名空间仍为`San9.Core.Domain`和`San9.Core.Simulation`；目录本身不新增依赖层或公共接口。

| 层 | 子目录 | 职责 |
| --- | --- | --- |
| Domain | Navigation | 领域地图、寻路、静态拓扑、行军计划与搜索诊断 |
| Domain | Military | 部队、阵型、设施、战斗与兵法基础规则 |
| Domain | Governance | 人物状态、能力、人事、官职与宝物规则 |
| Domain | Events | 历史剧情与特殊探索的内容定义；皇帝制度与官爵／国号规则仍归Governance |
| Domain | Economy / Diplomacy | 内政经济规则；联盟状态与外交计算 |
| Simulation | Movement | 日常行军与动态占用缓存 |
| Simulation | Combat | 交战、伤害、兵法、战后处理与占领 |
| Simulation | Military | 出征整编、主将、部队生命周期、方针及日级维护 |
| Simulation | Construction | 设施建设与撤除 |
| Simulation | Personnel / Governance | 人事与俘虏流转；军团与身份维护 |
| Simulation | Economy / Diplomacy | 经营与资源结算；势力关系与联盟执行 |
| Simulation | Events | 剧情候选选择、消费键与待答会话 |
| Simulation | Events/Historical | 历史剧情及季度历史表；包含通过登用或探索触发的官渡、山阳公与三顾 |
| Simulation | Events/Search | 特殊探索分支与探索事件调度 |
| Simulation | Events/Politics | 拥立／废帝及官爵／国号事件执行 |

跨业务的世界状态、事务、不变量、命令与领域事件基类、随机源及结算总入口留在各层根目录。新增文件优先进入对应业务目录，仅由某个业务维护的缓存与实现细节跟随该业务，不另建通用工具目录。

剧情按业务含义归档，不按调用入口机械分类；例如官渡由登用触发，仍归历史剧情。皇帝解析、人员转属、势力生命周期、日常人事与联盟规则继续由各领域目录维护，不因会产生领域事件就全部迁入`Events`。目录整理不改变命名空间、内容／保存契约或调用关系；通用事件插槽和内容模型仍按[后续重构计划](../../specs/plans/roadmap.md#原作事件解析后的系统重构后续计划)统一评估。
