## 扩展记录的编解码

### 字段顺序与长度

**事实。** `deserialize_extended_person_record(0x45D330)` 与 `serialize_extended_person_record(0x45D620)` 双向对应，按下表消费／产生231字节。小端整数读写不含记录ID，ID由调用方赋予。下表偏移只针对单条记录内容，不是文件绝对偏移。

| 偏移 | 长度 | 语义与运行时落点 |
| --- | ---: | --- |
| `0x00` | 2 | 列传资源码 → `+0x3C` |
| `0x02` | 2 | 头像资源码 → `+0x40` |
| `0x04` | 2 | 亲代人物引用 → `+0x94`；读取值≥850时置无引用 |
| `0x06` | 2 | 上下文人物引用 → 扩展对象`+0x12C`；同样检查850边界 |
| `0x08..0x19` | 18 | 九类`u16`熟练度 |
| `0x1A` | 1 | 出生年编码 → `+0x48`；读取直接存编码，年份解码沿用基础人物规则 |
| `0x1B..0x1E` | 4 | 基础武力、智力、政治、统率；各自写入基础值及当前值槽 |
| `0x1F` | 1 | 性别标志 |
| `0x20` | 1 | 信念 → 扩展对象`+0x128` |
| `0x21` | 1 | 性格 → `+0x78` |
| `0x22` | 1 | 义理 → `+0x70` |
| `0x23` | 1 | 野心 → `+0x74` |
| `0x24` | 1 | 寿命档 → `+0x7C` |
| `0x25` | 1 | 身份 → `+0x84`；读取值≥10时置无效身份−1 |
| `0x26..0x2E` | 9 | 九个精通字节；读取值恰为1时启用对应类别 |
| `0x2F..0x34` | 6 | 已习得兵法位集 |
| `0x35..0x39` | 5 | 姓内联文本 → `+0x10` |
| `0x3A..0x3E` | 5 | 名内联文本 → `+0x15` |
| `0x3F..0x43` | 5 | 字内联文本 → `+0x1A` |
| `0x44..0x4E` | 11 | 姓名读音遗留文本 → `+0x1F` |
| `0x4F..0xE6` | 152 | 逐槽列传文本缓冲 → 扩展对象`+0x130` |

总长为`8+18+12+9+6+26+152=231`。读入收尾调用`set_person_appearance_year_from_birth(0x44CDA0)`，派生登场年为出生年加14；记录不独立序列化登场年。出生年、自然年龄及年度登场的公共规则仍归[RE-0133](RE-SAN9PK-0133.md)。

**纠错事实。** 旧RE-0009将信念后的顺序写成“野心、性格、义理、寿命、身份”，与本次双向读写不符；正确顺序为**性格、义理、野心、寿命、身份**。旧资料称为“勇猛”的末项实际进入身份setter。基础134字节记录与本扩展记录均无独立勇猛字段；基础记录的完整负面审计保留于RE-0009。

姓名不查基础人物姓名资源，四段内联文本按5／5／5／11字节往返；基础人物资源物化及读音字段无玩法／搜索／排序／显示消费者的全程序核对仍归RE-0009。原作输入控件精确长度校验尚未定位，不能把存储容量直接当成已验收的输入上限或重制姓名长度。

### 登记文件与单人文件

**事实。** 文件用途沿[文件清单](../sources/s9-file-inventory.md)登记，以下入口在本轮复核：

| 入口 | 已确认行为 |
| --- | --- |
| `0x459BA0 → 0x453550` | 可选`D_TPrsn.S9`先检查版本`0x39221211`，再连续反序列化100项；扩展池步长456字节。缺失／版本不符不读取记录，仍进入后续复制阶段 |
| `0x455C20` | 把100个登记对象的普通人物部分复制到700–799槽，保留目标运行时类型与ID；随后处理血缘引用 |
| `0x459CD0 → 0x453590` | 保存同一版本头及大小`0x5AA0=23200`字节的数据块；池内序列化器连续调用100次，无逐条232字节对齐步骤 |
| `0x45D8F0` | 以姓、名拼接`%s%s.S9P`文件名，写4字节版本头和232字节数据块 |
| `0x45D7B0` | 单人读取相同版本头和232字节块，再调用231字节编解码器；可由参数指定目标ID，并有额外转换分支 |

**边界。** 编解码器实际消费231字节，文件块却按232字节／23200字节读写。单人块多出的1字节、整池末尾多出的100字节尚未有字段语义，不能把文件描述成“100条按232字节对齐的记录”，也不能把完整文件长度误写为`4+100×231`。若保存调用正常完成，写出长度分别为236与23204字节；这不是本轮实际文件样本的测量结果。短文件、额外尾部、异常引用及失败写入恢复尚未完成文件实验。

`dispatch_new_person_editor_state(0x560AC0)`的case6调用池保存器，清除编辑任务的已修改标志并回到状态1003；导入流程还有保存调用。批量生年调整仅已证实内存同步，不能据此宣称每次输入确认立刻写盘。跨作品导入入口虽已有函数名，不代表其映射、容量冲突和引用修复已逐项核查。

## 创建规则

### 默认值与信念

**事实。** `initialize_new_person_defaults(0x555220)`设置出生年150、四维各50、清空四段姓名及列传文本，设置头像和性别，再调用信念生成。这里只确认直接赋值，不把整个创建面板的状态初始化和所有随机生成入口标为完成。

`0x5544C0`依据五档选择值生成**义理和野心**，并非旧RE-0009所称“性格和义理”。本轮核对实际setter及反汇编分支：

| 信念代码 | 义理（含端点） | 野心（含端点） |
| --- | --- | --- |
| 0 | 11–15 | 11–15 |
| 1 | 11–15 | 0–5 |
| 2 | 6–10 | 6–10 |
| 3 | 6–10 | 11–15 |
| 4 | 0–5 | 11–15 |

`0x45D230`的反向分类按义理／野心阈值6、11恢复五档，`0x55F510`调用者明确传入人物`+0x70/+0x74`，提供独立参数语义证据。五个玩家显示名称尚未在本轮与消息资源逐项对应，不按代码顺序自行命名。反向分类也不证明任意义理／野心组合都会由正常创建生成。

“信念”这一玩家术语沿RE-0009记录的用户新人物界面观察；存储位置、五档值及其生成作用另有机器链支持，不以单一界面标签认定字段。

### 关系引用

**事实。** `0x552C90`的新武将“友／相性武将”选择只写扩展上下文人物引用并刷新界面，不直接修改人物`+0x6C`的相性数值。亲代在另一字段；不可把两者合并。扩展`+0x12C`在培养流程复用为指导武将，死亡、被俘或转属时的重选证据归RE-0149。

原PRSN-02证据的两个培养入口为`select_trainee_instructor_and_policy(0x40A4C0)`与`repair_invalid_trainee_instructor(0x40B8D0)`：前者从同势力候选中选指导武将并写`+0x12C`，后者在上述失效状态清空并重选，培养事件再经空安全访问器解析。这里保留跨生命周期复用的独有证据，不将该引用命名为通用“好友”。

该结论只排除“选择器立即改写相性数值”；后续开局关系初始化是否按此引用派生相性、亲缘或地点，仍须沿实际消费者核对，不能扩大为“该引用始终不影响相性”。

### 四维、兵法预算与秘籍

**事实。** 四维输入`0x552680`范围正常为1–99，秘籍标志开启后为1–100。`calculate_new_person_tactic_points(0x552440)`从35或秘籍10000起算，只遍历编号0–30的31项已选兵法并扣除各项成本，结果最低为0；这不等于全游戏只有31种兵法。完整成本派发表`0x552350`尚未逐项转录核验。

妖术编号30、事件号`0x41F`；处理路径`0x554C30..0x554C5D`递增编辑器`this+0x39AC`，达到20次后经`0x554910`置`new_person_tactic_cheat_flag(0x1A5E4B0)=1`并刷新选择。`0x553810`按`min(点数,99)`显示`%2dP`。旧“选中10次、取消10次”是操作配方，静态证据仅确认妖术事件累计20次，不存在已确认的两个独立计数器。秘籍标志在退出编辑器、重进菜单及重启后的清理时机尚未核清。

### 普通创建确认的派生值

**事实。** `finalize_new_person_record(0x554940)`在特殊姓名模板分支之外复制草稿到登记对象，设身份7并重算能力，随后生成寿命与熟练度：

- 普通寿命档：随机值0–99落在0–9、10–29、30–59、60–99时分别给4、5、6、7；秘籍强制7。这里是寿命档，不是死亡年龄。
- 只统计0–30号已选兵法，按其系统类别计数`n`；有兵法的类别写熟练度`200×n+随机0–99`，`n≥2`时精通；无兵法类别初始写0且不精通。
- 九类都有至少一种兵法时，所有类别均精通；若完全没选兵法，则九类均精通、熟练度分别为随机500–599。
- 秘籍收尾覆盖为九类均精通、各自熟练度随机900–949。之后同步普通人物副本及相关引用。

这些是创建确认函数的静态分支；不证明所有改名、修改既有人物或导入操作都会重新执行相同随机化。

### 特殊姓名模板与异常边界

**事实。** `0x554940`按特定姓／名资源组合分支，且要求登记集合尚无对应列传664／665，再经`0x459DD0/0x459E30`复制相应基础模板。`0x455D00`只检查登记集合，不保证基础模板存在；`0x45DAB0 → 0x45DA40 → 0x44C2F0`的`0x44C2F9`直接读来源指针`+4`，没有空检查。模板缺失时执行此路径存在无效访问风险。

这项原取证来自RE-0130关于固定人物引用的审计；它是**新武将创建确认**的特定路径，不能当作普通新剧本开局的崩溃复现，也不能解释为任意特殊人物死亡都会死机。特殊姓名的精确文本映射、可重复创建／改名和动态触发尚未闭合。

## 登记菜单与批量生年

### 批量平移出生年

**事实，原取证RE-0176。** `CMakeNewMainDlg`的`0x5567D0`在激活命令1001且Ctrl、Shift同时按下时，将返回码1改为8；`0x556DD0 → 0x560AC0`的case8调用`0x55FBB0`，普通case1进入单人变更选择器`0x55EB50`。仅按组合键不触发；无可变更对象时菜单禁用。

菜单初始化`0x5569F0`绑定第二项资源3628及提示8122；已转换消息8643为“登录新武将”、8122说明变更登记内容。`0x55FBB0`使用8423说明总括变更出生年、8424选择基准人物。独立文本证据来自忽略生成物`local/generated/research/unified-text/messages.json`的对应消息项。

先选基准，再输入其新出生年；确认后以`新生年−原生年`为统一差值，平移列表内全部有效对象。例如180改190，其余同时加10，保持年龄差。选择器或输入框取消均不执行写回循环。

候选谓词`0x471140`要求已占用、运行时槽700–799，排除列传664／665；`0x44D5B0`以身份−1判空。整体生年边界135／265，按最早与最晚生年求前后可平移空间，再转换为基准人物输入上下限；列表为空或两个方向都无空间时不打开流程。外部异常年份未验证。

写回`0x55FDD2..0x55FE55`经`0x44C250 → 0x4534D0`解析独立登记记录，对当前人物与登记对象都调用`set_person_birth_year(0x44BD70)`，并置已修改标志，最后回菜单状态1010。循环不直接改登场年、寿命或亲子关系；这不排除后续新局重新派生登场年。按钮反馈及保存重启尚无本轮动态验证。

## 新局接入与运行时状态

### 自创人物的新局整理

**事实。** 新局确认链`0x561430 → 0x45C120`首先调用`0x45B9E0`，遍历700起的100个人物。有效且非死亡者在非忽略年龄模式下若年龄大于90，改为身份8；其余复制逐槽列传、重新派生登场年、执行相关引用处理并继承同姓旗字，随后按身份／地点初始化，并对仍需处理的列表最多重复100轮。

忽略年龄模式值1绕过上述年龄清理；`scenario_id==18`作为另一参数传给状态／地点初始化，不应与281年编辑器工作基准的ID19混淆。其特殊部署意义及`0x450AF0`等关系消费者仍待核对，不能把外层循环已读完称为全部开局规则已完成。公共年度登场及自然死亡见RE-0133与相关生命周期研究。

### 自创君主城市兵役转化与增兵

**事实，原取证RE-0061。** `initialize_primary_force_leader_cities(0x456C30)`遍历50个势力记录，要求势力有效、为根势力、君主有效且`0x44C230`判定其运行时ID为700–799，并可解析君主当前城市。只处理该城市，不处理其全部领地；自创人物仅为部下时不触发，也不适用培养小兵。

`0x44C230`比较值经虚表`0x606110+0x4C → 0x446820 → 0x4467E0`读取人物`+4`低16位的运行时ID，不是列传码或被丢弃的文件ID。城市兵役人口getter虚槽`+0xE0`读取`+0x1C0`。规则为：

```text
转兵役人数 = floor(当前兵役人口 / 10)
兵役人口 -= 转兵役人数
增加士兵 = min(12000, 转兵役人数 + 5000)
城市士兵 += 增加士兵，受城市士兵容量限制
```

兵役人口50000时减少5000、增兵10000；并非固定加10000。旧用户观察未登记君主ID，不能推广到所有历史君主；董卓ID481不通过此门。`deserialize_city_record(0x43A8E0)`只读取文件`city+0x0C`并经`0x4373A0`按500000上限写入，没有附加这项增兵。
