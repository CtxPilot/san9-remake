## 八类计略

**共通门与距离的适用范围。**25～32在己方根元数据bit8成立时均50%跳过；29～32取当前战略对手（模式2势力／模式3建筑所属根）为目标，其bit7成立时再75%跳过。来源取直属可用城市。**25～28、30／31**先用`0x470910`检查来源城市到至少一项目标的几何时间闭区间0～元数据第3字节，取`ceil(两点欧氏距离/30)`，不是求路ETA；配对时再经`0x4AFDD0`要求执行者所在城市与当前目标地域城市相同或相邻。**29离间**直接使用直属城市的执行者，没有这两道地域近邻门；**32流言**通过`0x46E310`检查来源城市到两目标势力至少一方的君主当前关联地图对象中心，同样是几何时间，不是势力领地中心；配对时没有`0x4AFDD0`。不得把六项的近邻规则扩展为八项统一门。

临时真实命令先经过派生有效性，重建公共参与人物上下文，再从首位参与者所属根势力取得军师；无有效军师返回−1并使用实际公式，不会自动给100分。意见1→100、3→0、其他→真实阈值；25/26至少15，其他至少20。保留组合再按真实阈值稳定降序。公共选择器按目标外层顺序取首个可行组合；25～31选中后移除该执行者和目标，32只移除使者，28另有来源兵力不足的内部重选。随后才交公共命令验证，不是全体组合全局最优。军师输入来自真实公共命令上下文，不来自UI是否显示预测。

### 25／26：伪报与扰乱

交互 code 25 的 `COrderGihouDlg` 与 code 26 的 `COrderKakuranDlg` 均以虚表 `+0x20` 复验/填充、`+0x24` 消息映射、`+0x28` 创建命令。伪报要求目标满足单位有效、运行时标志 `0x8`、敌对/关系过滤和命令对象关联等条件；扰乱复用这些条件，并额外排除阵形类型 27。两者的执行者均要求人物有效且未置公共参与占用位 `0x1000`。

自动 code 25/26 先通过公共自动行动门，再建立目标、来源对象和执行者列表，任一列表为空即拒绝。两个执行者收集器都把人物当前有效智力限制在闭区间 `45..115`。目标扫描覆盖 850 个部队记录，排除同势力、兵力小于 5000、状态 4/5/7/8 和不匹配当前命令对象的部队；伪报优先没有己方部队已配置攻击它的目标，按目标成员最高智力升序；扰乱要求至少一个己方部队以它为目标，按成员最高统率升序，相关命令兼容谓词另排除自身及已占用状态。评分与配对沿本节共通规则，提交对应公共命令。

25目标命令归属检查使用当前**直接军团**，26使用己方**根势力**：先解析当前目标编码，缺省再用主目标；类型3／4／5分别解析单位／据点／城市。**解析对象有效且归属不匹配时拒绝；解析对象已失效时，这道候选门没有直接拒绝。**其他编码类型不进入后续分支。原文“必须指向有效己方对象”的概括由`0x4A55E0/0x4AC5B0`实际分支纠正；此处通过仍不代替后续配对和公共命令验证，不据静态入口宣称失效目标局面必然出令。25要求没有本直接军团合格单位正针对它，26要求已有本方根势力合格单位正针对它。两者都有`兵≥5000`和相同状态排除，但不能把根／直属范围差异抹平。

### 27／28：激励与救援

自动激励只保留状态不为 8、士气不高于 80 且通过目标虚拟谓词的部队，按士气升序；执行者当前有效智力限制为 `45..115`。自动救援目标必须同时满足：至少 3000 空余带兵量、士气至少 25、命令事件类型不为 51；事件类型为 39、40 至 50 或 52 时还须通过目标交战谓词。`0x4AE940`的虚槽`+0x90`由单位真实虚表`0x606490`解析到`0x461730`，外部部队主动／被动交战任一成立即可；普通攻击38不套此门。目标按当前兵力升序排序。当前遗漏返回目标交战门的公共诊断见[计略外交续核](audits/planning.md#note-2026-10-23-automatic-work-schemes-audit)。

自动救援先按`0x46CBE0`的驻兵闭区间过滤为至少6000，再检查至少3000（后一道为冗余）；关系mask0x10的重点区域且城市／关要求至少13000，区别于立即前线mask2。不能把6000误叫兵役人口。最终创建命令前还按来源的重要性和关联对象数计算保留量：基础为 `8000 + min(20000, 4000*n)`，特定来源至少保留 10000，最后再加本次要扣除的 3000；来源兵力不足就移除该处人物并重新选择。救援执行者当前有效统率限制为 `45..115`。当前来源预筛错用立即前线门会提前消耗目标的公共对照见[剩余条件续核](audits/planning.md#note-2026-10-24-automatic-work-remaining-audit)。

**2026-10-16补齐n的真实生成条件。**`0x4AE740`先通过`0x4B0770`收集以来源建筑为目标、事件38且已出发的部队，逐队求来源建筑到其当前位置的路线。路径上有类别7～10建筑则不计数；遇到另一有效建筑时，若其通过对该部队归属的`0x4B0700`谓词，或该部队到来源的ETA≥5，也不计数。ETA检查位于“另一有效建筑”条件内，不能简化为先对所有单位统一过滤ETA<5；路径为空或没有这样的建筑时，可直接计数。计数谓词没有同势力或额外几何距离门。`0x4AEB40`只把这个计数用于保留量，不提前执行救援；不足时移除该来源的执行者再内部重选。此为静态分支事实，不推测其设计动机。

取证身份：RE-SAN9PK-0114。

### 2026-10-24：“阿会喃系统”与离间目标的编号偏向

**调查身份：AI-ALIENATE-ORDER-20261024，事实／推断分开。**复用`SRC-SAN9PK-TC-101`、繁中PK 1.0.1.0主库及RE-0115；本轮回读SHA-256为`d20794aeff67301ec2bf8c3becb1e9944c68c6c0588fbfd4bf04e8597f0e5028`，PE32/i386、基址`0x400000`，IDA 9.4／Hex-Rays 9.4.0.260915。问题是自动离间是否真的按姓名比较排序，以及重制是否仍有相同的目标选择偏向。

**原作事实，静态高置信。**`collect_automatic_alienate_targets(4B13D0)`调用`472970 → 472890`：以人物容器`CPersonData`执行`46F280`，按容器虚槽`+0x0C/+0x10`枚举人物。真实虚表`606C8C`的两槽分别指向`470E30 → get_person_record(4531B0)`与`470E20`，即按人物记录索引从0向后扫描、原作域850项；不是在这里读取姓名字符串或读音并比较。`4716B0 → 44C0B0`按目标势力关系筛选，随后两次`46F330`过滤保持原顺序；`4B10C0`再保留忠诚≥70、当前智力≤90的候选，也没有排序。此处的原作固定域只描述源实现，不是重制人数上限。

公共目标选择器`4B0360`从目标表首项向后调用`4AF480`，首个能形成可行执行者配对的目标立即胜出；真实成功阈值等排序发生在**该目标的执行者之间**，不是在全部目标之间求最优。因此即使后面的目标更容易离间，前面的目标只要已有可行配对，就能先被选中。较早编号不符合资格或没有可行执行者时会跳过；选中后仍按既有规则消费执行者与该目标，所以不是一次工作里无限重复攻击第一人。

**与俗称的对应，推断。**这条链支持“人物名表靠前者更容易被集中离间”的外观现象，准确机制是默认人物编号／列表顺序成为了目标优先级。当前190年转换包的`officer.0`为阿会喃、`officer.2`为伊籍，与低编号受偏好的解释相符；这两个名称仅用于对照，不进入产品判断。改变显示姓名不会改变上述编号扫描链。玩家对旧版／PK／Steam版的说法不一致，本轮没有检查无PK旧版或Steam精确构建，不采用“所有PK都修复”或“Steam重新引入”的版本结论；也不把离间的证据外推为所有计略都按人物名表顺序选择目标。

**修正前的重制实现，代码事实。**`WorldState.Snapshot`按人物ID升序发布`Officers`；原`OriginalAiActions.Targets`的`Alienate`分支过滤后保留此顺序；`OriginalAiActions.Run`按目标外层遍历，遇到第一个`SelectPair`成功的目标便停止。`OfficerContentCompiler`以原版人物记录索引作为转换身份，因而同样出现低ID优先偏向；不能用“没有姓名比较”或“军师预测已经按阈值选执行者”证明此问题消失。独立内容的偏向取决于其自身ID顺序，不需要姓名具有任何特征。该缺陷已于后续v184按[B18](../../../specs/original-ai/behavior.md#b18)修正为过滤后使用独立规划随机线性洗牌；原作证据不因此改写。

**IDA实际变更与验证。**向`4B13D0`与`4B0360`各追加一条引用RE-0115／本节的函数注释，说明按人物索引保序与首个可行目标短路；不改名称、类型、边界或程序字节。保存后注释2/2精确回读，函数字节摘要2/2不变；账本见[alienate-target-order-20261024.json](../../archive/ida-write-records/alienate-target-order-20261024.json)。本轮未运行原作场景实验、修改产品代码或重复运行产品测试。

#### 日版PK 1.3.0.0对照：过滤后随机重排目标

**调查身份：AI-ALIENATE-JP130-20261024，静态事实，高置信度。**用户随后提供的`San9PK-clean.exe`确认为[SRC-SAN9PK-JP-130](../../sources/SRC-SAN9PK-JP-130.md)：版本资源1.3.0.0、日语、2,711,552字节，SHA-256 `182fb10b323f473da7eb40beff11beea4c1d259db0abc891d63a01cedcdf2513`。与RE-0150既有日版样本完全一致。本轮新建独立`San9PK-JP-130.i64`，使用IDA 9.4／Hex-Rays 9.4.0.260915；PE32/i386、基址`0x400000`。以下日版地址均由其公共离间公式`49A9E0`的调用者、自动配对回调及工作虚表反向定位，未按繁中地址加固定偏移推定。

| 环节 | 繁中PK 1.0.1.0 | 本次日版PK 1.3.0.0 |
| --- | --- | --- |
| 目标资格 | `4B13D0`以`4B10C0`过滤忠诚≥70／当前智力≤90 | `4B9930`以`4B95B0`执行相同两项过滤；这两门不是日版新增 |
| 过滤后顺序 | 保留人物记录索引顺序，之后即返回 | `4B99EF..4B99F5`取过滤后列表长度N，以该列表为`this`调用`475660(N)` |
| 目标重排 | 此收集器没有随机重排调用 | `475660`抽取列表元素到临时数组，随机交换后按数组顺序重建列表 |

**随机交换的精确边界。**`475660`在N<2时直接返回，不取随机数。N≥2时，每轮执行`floor(N/2)`次交换尝试，调用者传入轮数N；每次尝试独立调用两次`rnd(N,11,1)`取数组下标，同下标则跳过交换。因此总尝试数为`N × floor(N/2)`，随机接口调用数为其两倍。关键循环和`4B99F5`的实参均已逐条核对汇编；没有依赖反编译中错误显示的空数组指针或缺失的隐式`this`。该算法是反复随机交换，不据此声称所有排列严格等概率；随机结果也允许碰巧维持原顺序。

**结论。**该日版构建已经打破离间目标固定按低编号优先的机制。它采用“先随机重排合法候选，再找首个可行目标”，没有增加姓名特判，也没有改成所有目标按成功率／人物价值取全局最优。因此前述“编号保序”的当前样本结论限于繁中PK 1.0.1及重制当时实现，不能扩展到这个日版1.3构建；也不能以这个构建证明所有PK或Steam构建都相同。

**官方条目映射，推断。**这项差分与[2005-08-10履历](../../sources/SRC-SAN9PK-JP-PATCH-HISTORY.md)所述“电脑势力选择离间目标存在偏向”的修正方向直接相符，比单纯的忠诚70／智力90门更能解释该条目。但本轮没有修正前后的日版相邻构建，逐条官方日文仍沿既有用户转录边界，不能单靠当前最终版本锁定该代码首次加入的补丁版本。无PK旧版、Steam精确EXE及其他计略仍不在本轮对照范围。

**重制采用。**后续v184已按[B18](../../../specs/original-ai/behavior.md#b18)采用过滤后随机重排，使用现有独立规划随机与可扩展人物集合执行一次线性Fisher–Yates洗牌，再沿原流程选择首个可行目标；不复刻日版二次方交换次数。空表／单候选不为排序取随机数，恢复确定性由现有随机种子／续行状态机制承担。没有新增全局目标价值评分，日版研究事实与重制采用分别维护。

**IDA实际变更与验证。**日版主库对`4B9930/475660/4B8640`进行三个高置信函数命名并分别追加注释，记录随机重排、循环边界与首可行短路；繁中主库向`4B13D0`追加日版差分注释。名称dry-run 3/3无冲突，保存后日版名称3/3、两库注释4/4回读一致，四个函数的字节摘要不变。刷新反编译除符号／注释变化外，还自动补出了隐式`this`参数及临时数组分配／释放，纠正了初次输出的空数组指针假象；逐项与汇编对照，随机循环、列表重建与首可行短路语义一致。没有修改程序字节、手工类型或函数边界。账本见[alienate-jp130-comparison-20261024.json](../../archive/ida-write-records/alienate-jp130-comparison-20261024.json)。未启动原作或运行产品测试；本轮没有产品代码变化。

## 四类自动外交

### 33：赠与

交互 dispatcher 的 code 33 构造 `interactive_gift_action_task`，其 RTTI 对话框为 `COrderZouteiDlg`。对话框保存使者、目标势力和四字段载荷；取消返回空，确认后构造共享 `gift_command`。目标、使者、宝物或数量变化都会临时构造真实命令并走公共有效性和军师意见路径。

自动工厂 code 33 构造独立自动赠与任务。公共门拒绝不可用、已有禁止状态或特定势力标志的来源；随后从来源余量计算资金和兵粮候选，选择目标势力和一名使者，再由 `create_automatic_gift_command` 构造同一个共享命令。自动载荷不选择宝物：资金候选为扣除动态需求和固定 2000 后剩余量的一半、上限 10000；兵粮候选为扣除动态需求的 1.5 倍和固定 10000 后剩余量的一半、上限 10000。资金不足 1000 且兵粮不足 10000 时放弃；否则比较资金与兵粮的十比一等价值，二选一。

自动目标评分同样临时构造真实赠与命令。军师结果 1、2、3 分别映射为 100、50、0；其他结果使用公式 11 的真实阈值，再要求阈值落入候选记录给定区间。若目标或使者列表为空，自动任务不产生命令。
