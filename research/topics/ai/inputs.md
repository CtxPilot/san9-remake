## 公共决策输入

不同工作共享路线、能力、主将和资格查询，但其筛选口径不同。以下先定义共同输入；各工作章节保留自己的额外门、排序和计划状态。

<a id="shared-candidate-contracts"></a>
### 来源、人物、对象域与策略敌对资格

**事实，AI-BOUNDARY-20261016-O。**以下条件来自实际共享收集器和下层getter；它们限定使用这些入口的工作，不外推成所有AI行为的统一过滤。

| 查询 | 实际条件／返回口径 |
| --- | --- |
| 城市来源`0x4B03C0`、地域建筑来源`0x4B04B0` | 先按当前**直接军团**归属收集，再以`0x4AFEA0 → 0x436180`要求内嵌驻军的**查询状态码**为1；不只检查对象存在和归属 |
| 查询状态`0x45EBF0` | 原始状态不是1就直接返回；原始1且交战虚槽`+0x90`为真时返回2，不改原始字段。因此“原始状态1”不足以通过上述来源门 |
| 地点人物`0x4AF840` | 经`0x436CC0 → 0x435940 → 0x460E30`复制地点内嵌单位的成员顺序；输出总人数在身份／行动过滤**之前**取得 |
| 可行动人物`0x4AF6C0` | 原身份掩码15保留0～3，再以`0x472D30`排除`+0xE8`的`0x1000`占用位；该层没有附加“必为身份3”、能力下限或根级全领地扫描。能力门由各工作另加 |
| 类型化全表收集`0x46F280` | 按容器虚槽给出的域及索引顺序扫描，检查对象有效性／运行时类型，再执行谓词。地域建筑域250、城市域50；通用单位域1100，含250个建筑内嵌驻军及850个外部单位 |
| 显式外部单位扫描 | 58准备、25／26目标收集明确循环850个外部单位；不得把通用单位容器也缩成850，或把这几个显式循环扩大到驻军 |

上述数量和索引顺序是登记样本输入域，不是重制对象数量上限。`0x453330`将单位域0～49映射城市驻军、50～249映射其他地域驻军、250～1099映射外部单位。当前槽是否启用仍由有效性和各谓词决定；实际筛选后才有业务候选。

策略敌对谓词`0x4B0670`按以下顺序执行，调用它的建筑包装为`0x4B0700`：

1. 来源／目标有效、不同根，且目标非异民族，否则拒绝。
2. 来源为联盟成员或盟主时，目标为联盟讨伐对象则**直接通过**；否则目标也为联盟成员／盟主则拒绝。
3. 其余检查双向攻击请求配对，存在则拒绝；最后要求目标关系档<3。

第二步的直接通过发生在请求配对和关系门之前，不能在现代公共查询中改为“先检查全部保护再放行”。它与普通接近选敌的`0x4453E0`不是同一契约；后者关系门为<2。此处只描述原作资格，不决定重制是否采用差异。

<a id="candidate-order-and-random"></a>
### 列表顺序、重复引用与随机消费

`0x46F430`先按输入列表顺序为每项计算一次键，再稳定插入排序；模式0降序、模式1升序，同键不交换。列表不足两项时直接成功，不调用评分回调。`0x46F330`按输入节点顺序过滤并追加，末参控制是否先清输出；`0x46EF80`只追加，不去重。交集`0x46F670`按第一张表顺序保留第二张表包含的项，不采用第二张表顺序，也不自动删除第一张表的重复引用。来源分配表、成员表与建筑邻接生成器是否去重须分别核对，不能用一个集合替代全部列表。

`select_random_list_value(0x46E900)`总会调用`rnd(列表长度)`，但随机入口调用次数与随机状态推进次数不同：[RE-SANCALC-0001](../../findings/RE-SANCALC-0001.md#rnd-与-kakuritsu)已用DLL代码及32位探针确认，`rnd(N)`在N<2时不推进全局流；`kakuritsu(p)`仍执行`rnd(100)`，p≤0或p≥100也会推进。因此单候选随机选择不应额外取一个随机数，确定失败／成功的概率调用也不能直接删掉。58不同兵法分支的短路顺序、特殊编队先随机再覆盖仍按对应正文维护。

<a id="pair-score-contract"></a>
### 配对可行分数与实际排序

**事实，高置信；AI-SPEC-READINESS-20261016-P。**目标外层选择器`0x4B0360 → 0x4AF480`调用工作虚槽`+0x34`，后者经`0x46F770`逐个执行者先算可行性、通过才算排序键，稳定降序；并非先完成全表预测再统一求键。单候选仍调用这两个回调，不能套用`0x46F430`的少于两项免评分分支。

| 工作 | 可行分数闭区间 | 与排序的区别 |
| --- | --- | --- |
| 23 | 20～INT_MAX | 军师3→0，其余（含无军师）→100；通过者按当前政治排序 |
| 24／56、27～32、34／35 | 20～INT_MAX | 各工作映射后的预测分数决定可行性，另用各自真实阈值或专精键排序 |
| 25／26 | 15～INT_MAX | 与上述相同，只有下限不同 |
| 33／36 | 33～100 | **同时检查上限**；通过后另用实际阈值排序，不按映射的100／50分排队 |

赠与／劝降不能简化为“至少33”，登用等也不能先把真实阈值夹到100。劝降公式`0x491280`没有最终100封顶；无有效军师走真实公式时，超过100会被36的配对上限拒绝，而意见1映射100可通过该分数门。此为条件数据流事实，不声称所有前置资格或该边界的自然运行局面已验证。重制按[B17](../../../specs/original-ai/behavior.md#b17)取消33／36上限；原作区间事实不变。逐工作入口、原始字节和标注见[规格前核查账本](../../archive/ida-write-records/original-ai-spec-readiness-20261016.json)。

<a id="analysis-state-effects"></a>
### 预测上下文、临时评分与缓存失效

**临时命令并非纯查询。**`0x485BC0`构造单执行者命令时会清空公共参与人物表并追加本次执行者；`0x48EFF0`、`0x496FE0`、`0x498B80`还分别覆盖返还、请求、赠与的全局谈判上下文。`0x486480`先验证命令，再从该参与者上下文解析所属势力及军师。原作串行预测／生产依赖这种覆盖关系；正式命令再次构造自己的上下文。以上写入不等于已付款、已派遣或已占用人物：人物`0x1000`由实际执行准备`0x492F50`或明确调用`0x486150`的执行链设置。不能把军师预测复用成正式执行，也不能将这些构造器假设为可并发、无共享状态的查询。

**评分会写对象。**58的`0x4A2440/0x4A2CB0`将候选分数写到目标对象`+0x08`，并写任务ETA数组；公共排序器只读取这些分数时才是一次性取键。58准备改写对方当前临时目标的独立副作用已在[部署准备](military.md#re-0080-事实准备阶段)登记；本节不重新决定其产品取舍。

| 保存的数据 | 生成、重用与失效 |
| --- | --- |
| 地域关系mask缓存 | `0x475980`首次分配，各势力行初始标脏；嵌套查询包装仅增加持有计数，不保证每次重算。`0x476490/0x476570`在行脏或强制参数成立时经`0x475DF0`重建，再清脏标记 |
| 归属／成员变更相关缓存 | `0x453D30`标脏相关人物／对象索引及指定根索引的关系行，传无效势力时标脏全部关系行。已核对调用者含建设初始化／移除／落成、建筑占领、新设／合并军团、对象转属和关系更新；它不重算人员配额 |
| 完整地图／事件刷新 | `0x453D70`标脏多张索引、邻接表和全部关系行，并调用`0x4AD170`；已确认入口为地图初始化和对应地图事件应用，不泛化成所有命令都全表刷新 |
| 建筑关联表 | `0x4775D0`首次构造或脏／强制时重建，`0x477360`按生成顺序记录不同关联对象；其局部去重不改变普通列表的追加语义 |
| 58预计时间 | `0x4A43B0`每次选择下一计划前调用`0x4A11C0`，将任务`+0x19F4`起850项置−1；选择过程中再写本轮分数。属于一次选择中的重用，不是整项工作或跨旬有效的ETA缓存 |
| 58慢地形标记 | 独立数组由`0x4A1640`写、`0x4A1670`读；上述ETA清空函数只清ETA区，不同时清它。不能把两个数组合成同一有效期 |

缓存标脏与目标引用清理是不同机制。军团记录退休时`0x455500`清除其他势力指向它的场景对手引用及内部势力目标；合并转移实际资产后重置源记录。9保留已有计划的快速路径仅检查来源表非空及目标对象有效，不重新执行全部关系、排序和强度筛选；各工作准备仍按各自生命周期进行。主将死亡／读档重选见前文公共主将规则；任官执行`0x48AE30`还在写官职与忠诚后修复军团负责人并重选所有非空单位主将，因此同旬后续军事规划读取的容量、忠诚与负责人可能已改变。

这些为2026-10-16登记样本的静态写入／调用事实。完整跨工作动态对照尚未执行，静态组合结果与局面边界见[附录](evidence.md#boundary-composition-evidence)。

### 路线与预计行军时间

<a id="re-0080-事实ai-确实求路预测但不逐日演算"></a>
#### 求路与时间换算

`0x468870 → 0x44A680 → 0x44A4C0` 是单位路线预计时间链，不只是界面显示。直接 AI 消费者包括 `0x49E420`、`0x49EAA0`、`0x49F160`、`0x4A2440`、`0x4A2FD0` 和 `0x4A3BB0`；组1选择器 `0x4A2CB0` 自己构造路径后直接调用 `0x44A4C0`。

`0x44A680` 构造粗格图并调用 `solve_square_path_graph(0x478290)` 一次，去掉起终格，以及目标是建筑时完全落在其占地内的尾部格，再统计剩余路线。普通类与 `terrain_family == 4` 类分别计数，预计时间为：

`ceil(10 * n0 / rate0) + ceil(10 * n1 / rate1)`

两移动率来自 `0x464740/0x4647D0` 选择的阵形机动力字段；选择器含特殊状态/阵形分支，不将它们概括成固定的两种速度。公式已逐指令核对 `0x44A4C0`。原先“慢地形”是该谓词的历史命名，不意味着这里简单把每格乘1.2。

这条预测链没有逐日调用 `compute_unit_daily_movement_step`、细步碰撞或前视路点推进。路径选择仍受粗图阻挡、对象软代价和连线偏好影响，详见 [RE-0136](../../findings/RE-SAN9PK-0136.md)；**选路代价与时间换算分开**，预测不把设施+50、单位+5/+40等搜索惩罚直接当作时间相加。因此是有路线依据的近似预计，不是保证实际抵达日的完整模拟。

取证身份：RE-SAN9PK-0080。

<a id="re-0080-事实也有重复开销不能把原作当成性能最优实现"></a>
#### 空路径、零速率与调用上下文

`0x478290`先清输出，求路失败不填路径；`0x44A680`忽略失败标志，剥除端点后交`0x44A4C0`。正机动力时空表返回0，所以同粗格、剥空的相邻路线和失败路线不能由此ETA区分。`0x44A4C0`两项除法均无零保护，不能编造“零速率返回无限”。机动力来自阵形`+0x5C`／源`jnki+0x10`；有效状态5～7用阵形27，常规慢地形用副船，失效船默认20、失效阵形默认10。登记20正式剧本的28项原始机动力逐项为8～26，均非0；这是原始数据核对，非仅以当前转换包证明。异常Mod／损坏输入的原作除零仍不转成产品要求。

时间上下文：`0x468870`用于57、58和救援保留量，读取单位当前主阵／副船速率，走对象路线与目标建筑尾部剥除；`0x461490`用于事后命令候选门，读单位主阵／副船原始机动力，引用无效返回调用方给定的INT_MAX；58组1按候选当前速率换算已求路线，再加其人员任务行程倒计时`+0x44`，不读取出发等待`+0x48`，见[时限输入](military.md#deployment-time-inputs)。`0x44A540`是两坐标路线入口，剥首尾但没有目标建筑覆盖尾部处理；其直接调用者为`0x473640`和交互预览`0x4DE850`，不能把UI预估口径提升成所有AI的统一上下文。`0x44A470`仅在全局建筑压力标记中使用几何时间估计，未经过求路。

#### 重复求路与节点模板失效

- `0x49E420` 的“小于5”已通过公共估计器求过路，成功后又构造一条路线检查建筑；两次路线起点上下文不同，不能未经验证就合并结果。
- 组0 `0x4A2440` 先算时间，通过后 `0x4A1480` 再求路线检查阻挡/地形。
- `build_square_path_costs(0x47A400)` 确有基础地形节点模板 `src_14`，每次复制后叠加动态对象和连线代价。这是基础节点缓存，不是完整路线缓存；失效生命周期：`0x479E40`释放并置空，经跳板`0x479E80`在设施移除、破坏、建设落成流程调用，另在主程序清理调用。`0x47A400`首次求路时只缓存静态节点、阻挡位与10/12地形基础成本，每次复制后重加建筑／单位及连线折扣；没有按势力或起终点保存完整路线。原作固定地图下的这套依赖不证明任意Mod换图可安全复用。
- 原作链中存在大量对象有效性及运行时类型检查。它们的存在不构成重制热路径也应保留同类检查的理由。

取证身份：RE-SAN9PK-0080。

未发现两档难度直接改公共伤害、四维或成功率；世界`+0x76`的电脑强度百分比是独立规则，见[RE-0071](../../findings/RE-SAN9PK-0071.md)。

<a id="re-0174-当旬新出兵的反应时机2026-09-30补证"></a>
### 下令、出征标志与电脑反应时机

- **事实：下令已创建，尚未进入每日阶段。** 普通出阵执行器`0x48BD20 → 0x485FA0 → 0x465450`立即创建部队、扣除来源兵力并写入目标。初始化通过部队虚表`0x606490 +0x14 → 0x4615E0`清零`+0x20`旗标；普通出阵路径没有置bit3。`0x461E40`写命令事件时设置的是其他旗标，不是bit3。
- **事实：玩家先规划，电脑后规划，然后推进日期。** `0x50EC90`按既有排序逐个等待交互／自动任务完成；正常直接控制主军团先于电脑主军团。`0x507DA0`等待整个军团行动阶段后才启动日期模拟，详见[RE-0123](../../findings/RE-SAN9PK-0123.md#命令生效时机复核2026-09-06)。
- **事实：每日预命令阶段置bit3。** `0x50E8F0 → 0x50BD00`对非bit1单位检查`0x463B70`（命令事件类型38至52），通过后以掩码8置位，随后递减`+0x48`出发等待。置位不要求等待归零，也不检查是否已移动出城，因此“已出征位”不能严格解释为物理离城。

**时序推断，高置信度：**常规玩家出阵后，紧接的电脑规划能读到新队，但bit3尚未置。高级可在上述路径当旬纳入候选，初级通常等每日置位后到下一旬纳入；仍须通过人物、兵力、关系、路线及预算，不保证出兵，也不推广到初级全部主动出击、既有部队接敌或改令。

取证身份：RE-SAN9PK-0174。

### 主将选定与死亡／读档重选

公共出征执行器对成员稳定排序后确定主将；阵位与主将资格分别处理。以下为登记样本的静态调用与指令证据，未作该组原游戏黑盒对照。

#### 普通出征

`execute_unit_deployment_command(0x48BD20)`先按输入成员对应关系写入各人的兵法与阵位，随后在`0x48BDC6`调用`0x46F610`，比较器为`0x471CA0→0x44DBE0`，模式0。`0x46F430`确认这是降序稳定排序，相等键不交换。然后`0x485FA0→0x465450`接入排序后的成员；`0x463270→0x4631E0`维护身份特殊成员及归属，`0x460A40`清除成员负责人标记并给最终链表首成员置位。因此“排序后首位”不能换成“用户输入首位”，阵位也不等于主将资格。

`0x44DBE0`在正常源数据范围内依次比较：

1. 身份：君主高于都督，高于其他身份。
2. 个人官职的指挥/带兵上限量级（除1000）；无有效官职时按10处理，即10000量级。这里读取的是个人`shak`官职，不是势力`kans`爵位。
3. 仅当官职指挥量大于10000时，再比较官职顺序，源官职ID较小者优先（键为77减ID）；指挥量不超过10000或无官职时，这一层为0。
4. 当前统率（人物运行时`+0x68`），不是基础统率，也不是第一比较项。
5. 整个键相同保留成员原顺序，没有武将ID兜底排序。

字段交叉依据见[官职](../../findings/RE-SAN9PK-0011.md)、[当前能力](../../findings/RE-SAN9PK-0095.md)及[不同负责人排序键的区分](../../findings/RE-SAN9PK-0122.md)。自动出征`0x4B3960`也使用这套比较器，不能将其概括为任意输入首位。

#### 主将死亡及读档重选

`kill_person(0x452190)`在负责人死亡且原对象仍有成员时调用`0x462800`；`relink_scenario_units_after_load(0x4533C0)`同样调用此函数。`0x462800`对君主/都督走专门优先分支；普通候选比较`0x44DBE0`，只在新键严格更大时替换，同键保留先遍历者。`0x460BC0`负责实际标记、成员前移及身份约束，并保护现有君主/都督关系。因此原作的重选不是“最高统率→武将ID”。未逐个核验所有离队原因，但死亡与读档两条路径已直接闭合；不能把身份特殊分支简化成不带前提的普通排序。

### 主将性格与人物字段口径

以关羽 ID 95 作身份锚，读取仓库内 `D_Sce001.S9` 至 `D_Sce020.S9`。20 份正式剧本的 `prsn +0x30/+0x32/+0x34/+0x36` 均为：

`75, 15, 3, 1`

暂停运行时 Person `+0x6C/+0x70/+0x74/+0x78` 也是同一序列。结合关羽相性 75、义理 15、野心 3 和性格档 1，确认正确业务顺序是：

| 剧本偏移 | 运行时偏移 | 业务字段 |
| ---: | ---: | --- |
| `+0x30` | `+0x6C` | 相性 |
| `+0x32` | `+0x70` | 义理 |
| `+0x34` | `+0x74` | 野心 |
| `+0x36` | `+0x78` | 性格 |

这推翻 `RE-SAN9PK-0009/0081` 的旧顺序，但不改变响应公式的数值表达。敌接近、自动撤退和追击响应读取的是性格档 `A`。
