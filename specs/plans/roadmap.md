# 核心玩法优先路线图

状态：已采用的阶段范围与退出条件。规划不等于行为已经确认或实现；具体目标由BEH定义。

## 当前进度

G00–G10已完成阶段验收，证据统一见[历史阶段索引](../../docs/history/README.md#核心玩法阶段)。G11／G12尚未完成；[原版AI](../original-ai/README.md)的OAI-00～05已完成生产接线与阶段出口，OAI-06原作对照和十年全图验收仍待完成。旧自主增强方案已归档，其算法与强度目标不作为本路线的前置。

[表现层](presentation.md)与AI并行，G13契约随具体场景补齐。正式新局、操作菜单、逐日推进和媒体已有接线，实际覆盖与画面／试听状态由表现层计划维护，本页不复制逐次接入记录。

## 目标与范围

核心玩法以可脱离 Godot 运行、可保存恢复、可自动对局为目标；表现层与原版 AI 并行推进。阶段完成以可执行玩法和世界不变量为依据，不以类、接口、规格或测试数量为依据。

本路线图替代原 M0–M6 的开发排期与阶段门槛；沿用既有产品范围和已确认行为决策。首个完整验收内容为 190 年正式剧本全地图，最终面向 Windows、macOS、Linux 单机。教学／挑战剧本、多人、原版存档导入及公开模组 API 不进入本轮；资料／新武将编辑器与发行版内容准备已由各自规格定义，不再沿用早期的整体排除。原版资源与生成包不入库。取消旧计划“先做带界面的垂直切片、到全地图 Alpha 才建设正式 runner”的依赖。

这里的“核心层、领域层”统一落在 `San9.Core` 内部，不新增重复的 Domain 工程。Core 拥有确定性状态和规则，Application 组织新局、玩家/AI 控制、交互会话、保存及查询；Content 与 Importer 补齐玩法输入。Rendering 与 Godot 的表现接入按独立计划推进，共享契约保持一致。

本轮按正式版标准完成约定范围内的核心玩法。除本路线图及已采用规格明确排除、推迟或归属后续阶段的内容外，当前阶段的行为必须完整实现，不以原型、简化版或“以后再补”交付。后续阶段承担新增玩法及其接入，不承担纠正当前阶段已知的规则缺口；正式核心实现不等于表现层及发布验收已经完成。

无需先完成全游戏逆向，但正式实现前必须定向核对当前行为依赖的资格、输入来源、计算与随机、执行时机、副效果、最终写回及失效清理，并明确状态所有者和跨阶段依赖。已选规则遵循现有 BEH；缺失或矛盾证据先调查，再明确目标、来源与验收。重制选择须有明确产品理由，不能仅因研究未完成而用简化规则替代。影响当前结果的未决项解决前，不将相应行为计入完成；继续推进不依赖它的工作。不为原版内部存储建立兼容分支，也不预先设计通用策略游戏引擎。

证据核对使用已有RE及必要的IDA Pro／本地MCP调查，具体流程见[研究规范](../../docs/development/research-method.md)与[逆向规范](../../docs/development/reverse-engineering.md)。

## 后续：任务物理坐标与行程流程

2026-11-02用户确认列为后续，本轮不扩展实现、不预建坐标字段或服务。当前任务仍以路线、进度和到期日运行；登用／离间的完成返程使用结算时解析的目标地点。尚未实现人事／使者任务的独立途中物理坐标，不能将当前服务据点或保存的路线端点当作实际途中位置。

后续作为一项完整流程推进，不只补地图图标：

- 明确Core中的坐标所有权和覆盖任务：人员移动、探索、登用、计略使者、外交及返程；区分执行者实际位置、服务据点、人物目标身份和目标位置，避免各消费者自行推算。
- 接入每日物理推进、移动目标的坐标解析与追随，并保持物理到达、任务倒计时和到期资格各自语义清楚。是否调整现有到期规则须在启动时明确，不因补坐标自动改成“追到才结算”。
- 一并核对正常成功／失败、中止撤回、登用改属与旧任务清理、返程目的地失守／撤除及再次改道；明确替代据点选择的距离参照，以及新返程时长采用原版剩余倒计时修正还是实际位置距离。列为后续不表示已决定更改计时公式。
- 按需接通应用查询、发生时位置事实和地图人事单位显示；显示消费同一运行态，不另建影响规则的动画坐标。
- 持久化准确恢复坐标、进度、目标引用及日内阶段，按实际结构变化同步保存／命令脚本协议；验证确定性、跨旬占用、连续改道、人员与携行资源不重复处理，不恢复已延期的录像要求。

启动时细化目标行为与验收。当前已知差异及原作“每日坐标推进与倒计时独立”的证据见[人物行程核查](../../research/notes/2026-11-02-person-target-journey-audit.md)；现行任务行为见[人物行程规格](../behavior/BEH-PERSON-0003-recall-movement-and-action-reservation.md#未决问题)。本项不作为当前登用阻断修复与返程口径统一的交付前置。

## 独立开发支线：人才提拔培养

人才提拔培养（小兵培养）整体移出重制主线，作为独立开发支线目标，以后按需启动。覆盖触发、候选生成、导师与策略、培养成长和事件、完成人物生成及对应交互。它不是G09或G10的交付项，也不属于G12/G13主线完整性验收，不作为主线阶段前置。普通人物成长、登场、伤势死亡与继承仍归G09。

保留[培养规格草案](../behavior/BEH-PERSON-LIFECYCLE-0003-trainee-development.md)及其研究证据；支线启动时明确玩法、容量、随机与SL行为和验收，不预建空运行时服务或占位状态。本次范围决定替代旧G09培养要求。

## 阶段交付

**新大阶段开始前必须保证 Git 干净。** 每个 G 编号为一个大阶段；从一个 G 阶段切换到下一个之前，先完成当前阶段的相关验证、文档整理和提交，再执行 `git status --porcelain --untracked-files=all`，输出必须为空，即暂存区、工作区均无未提交改动，也无未忽略的未跟踪文件。忽略的本地资源和生成物不计入该检查。同一 G 阶段内部的子项不要求逐项清空工作区。不得通过丢弃改动、临时 stash 或新增忽略规则绕过阶段门；已有无关改动应保留并先明确归属、妥善收尾，未满足条件时不启动新阶段。

开始阶段先核对实际前置与有效证据；相同代码、输入和相关配置已通过的验证可复用。局部实现与阶段收口的验证范围按[工程流程](../../docs/development/engineering-workflow.md)和[测试说明](../../tests/README.md)选择；独立CLI、命令脚本与190年集成在大阶段收口时集中执行，不重复作为每个子项门槛。按当前用户分工安排视觉检查，不沿用早期“所有阶段不得启动游戏”的限制。

交付说明目标行为、实现、实际验证与剩余边界。阶段切换要求的收尾提交采用英文`type(scope): summary`；单阶段是否提交遵循用户要求。数据核对遵循[内容管线](../../docs/client-content.md#接入前的数据核对)，原作事实与重制选择按[研究规范](../../docs/development/research-method.md)区分。保存、精确恢复、确定性和显式命令脚本继续贯穿；录像不属于日常要求。

执行过程中可依据证据拆分、调整顺序或合并阶段，保持状态所有权、依赖和退出条件清晰。路线图改变开发顺序；若涉及已确认玩法取舍的实质改变，更新相应 BEH/DEC 并说明替代关系，不能仅修改本页来隐式覆盖规则。

## 后续：随机与玩家录像交付

以下仅登记后续考虑项，不纳入已完成阶段退出条件，也不预建接口：

- **其他外部不确定输入。** 玩家读档生成运行种子及固定条件／运行随机分类已按[随机约定](../behavior/BEH-SIMULATION-0002-randomness.md)接入，精确恢复保持种子和流状态。日常规则继续使用确定性伪随机；未来网络等额外输入须明确记录和重放注入，不默认沿用未记录外部输入。
- **录像整体延期。** 2026-10-22撤下现有调试录像及专属验证，不作为日常开发或阶段收口要求。未来有明确需求时重新设计全程回看、跳转、接手及长期存储，不保留空接口；见[延期边界](../behavior/BEH-SAVE-0001-session-persistence-replay-and-headless.md#面向玩家交付前的后续要求)。
- **存读档与未来录像。** 普通存档和精确恢复独立维护；未来是否支持录像续接、回退和分支保留，在重新立项时确认。
