# BEH-SIMULATION-0002：随机判定、SL与精确恢复

- 状态：已确认
- 关联决策：[DEC-SIM-0001](../decisions/DEC-SIM-0001-determinism-and-saves.md)
- 继承方式：归整既有采用语义，运行行为不变

本规格落实[确定性决策](../decisions/DEC-SIM-0001-determinism-and-saves.md)。验收关注操作顺序、SL与精确恢复；算法、种子组合和流划分采用现代实现，不要求原版同种子同结果。

## 重制行为

### 两类玩法随机

正式客户端每次创建新局（包括启动游戏和菜单中新开游戏）时，使用系统随机源生成一个64位本局种子，不再固定为`190`。种子在新局创建入口生成，Core仍只接收显式种子；存档沿用现有种子保存与恢复契约。客户端受控世界验证继续使用固定种子`190`，测试和诊断使用明确种子以保证可复现。随机生成不保证不同新局的种子绝不碰撞，也不保证每项随机结果都不同。

**固定条件随机**使用不变的本局种子、用途、下令日期、执行者及目标身份计算百分骰。没有共享抽样游标，不依赖命令ID、提交序号或本次运行种子。完全相同的条件得到相同骰子，先提交其他操作、读档或重启进程不会改变它。不同输入可以产生不同骰子，但百分骰只有100种取值，不保证输入改变时数值必变。现有算法使用Ordinal用途名、InvariantCulture数字文本和项目自有SplitMix64。

**运行随机**使用`RunSeed`派生具名流，同一次运行中逐次推进；不同用途互不消耗对方的随机数。同一用途内仍按实际结算顺序抽样。正常玩家读档生成新的64位运行种子，并清空旧流的游标，因此未来抽样可能改变。新局以本局种子作为首个运行种子，便于受控启动；运行中的规则不读取系统时钟或系统随机源。

固定的是骰子，不是最终成败。其他操作改变忠诚、能力、目标可用性或候选集合时，实时阈值与分支可以改变；硬条件不满足也不会因SL而强制成功。

战斗、兵法及战后各执行器按具体判定使用运行随机；计略／外交的提交级骰与分支效果分开分类，不因共用命令而共用所有随机。资格、确定公式和季度忠诚回归不抽样，不为未来系统预建空流。

原作完整调用清查见[RE-0171](../../research/findings/RE-SAN9PK-0171.md)：八类计略、赠与、攻击请求和劝降均有固定提交骰，但夺取宝物等分支另有运行随机；俘虏返还保存的骰子未被实际谈判消费，不能为复刻字段而引入概率。军师意见、地点提示也有固定概率组件；培养使用带局部计数器的独立序列，不能整体归为无顺序依赖的固定条件随机。各系统按实际判定分别分类。计略和外交的已采用分类见[计略规格](BEH-STRATEGY-0001-command-advice-and-resolution.md)与[外交规格](BEH-DIPLOMACY-0002-command-negotiation-and-resolution.md)；培养整体归[独立开发支线](BEH-PERSON-LIFECYCLE-0003-trainee-development.md)，不纳入主线随机接入要求。

### 跨系统边界

季度联盟提案发布后保留目标及已答内容，继续答复不重抽；待答不可保存。计略提交固定骰，流言包含两个目标身份，后续忠诚、关系幅度和成长使用独立运行用途；夺取的宝物门、人物选择、资金、关系幅度与成长彼此分流。意见只读推算，不推进这些流。人物生命周期、单挑及战后按各BEH的短路和抽样顺序执行。人才培养仍为独立支线，启动时另定局部序列和SL行为。

## 状态与不变量

同一初态、有序操作及随机状态得到相同结果；只读查询和拒绝操作不消费领域随机。固定条件骰不包含运行种子、命令身份或提交序号。

### 保存、玩家读档与精确恢复

- 存档保存`InitialSeed`、`RunSeed`、已消费的命名流状态及完整世界和任务。已写入任务的`SuccessRoll`属于已确定状态，任何读档都不重抽；改的是未来抽样。
- `SaveService.Load`为玩家读档：完整验证原文件和状态后，生成不同于原运行种子的系统随机值，建立新会话并清空运行流。保留世界、任务、命令水位、年表及最近记录，不重跑新局或旬准备。失败加载不会修改原会话。
- `SaveService.Read/Decode`、`GameSession.Restore`为精确恢复：原样保留两个种子和流游标，用于检查点、诊断、事务副本和命令脚本复现。不得在底层`WorldState.Restore`中自动换种子。
- 录像已延期并撤下，不维护片段、续接或录制开关。
- 新增运行种子属于状态契约和规则版本变化，未知格式存档明确拒绝，不默默使用默认种子。

CLI：`run --load PATH`表示玩家读档后执行命令文件；`run --restore PATH`表示精确恢复后执行，二者互斥。命令文件本身只描述操作；从不同运行状态执行同一文件可以得到不同结果，命令脚本本身不携带完整起点，中途复现须配合精确恢复。

额外常驻状态是一个64位运行种子；每次玩家读档仅生成一次系统随机值，日常判定仍是少量整数计算。不增加每颗骰子的日志、密码学哈希或系统随机调用；未把这一分析当作性能实测结论。

## 验收标准

- [ ] 固定条件骰不受运行种子或无关操作顺序影响；输入变化不要求百分骰必然不同。
- [ ] 玩家读档换运行种子并保留已确定骰子；精确恢复保留随机状态，与连续运行结果一致。
- [ ] 查询及拒绝操作不消费随机；各具名流互不干扰，各系统遵守自己的短路与抽取顺序。

本表是既有语义的验收要求，本次文档归位未重跑产品回归；已有证据见[存档规格](BEH-SAVE-0001-session-persistence-replay-and-headless.md#验收标准)。
