## 适用范围

本规格约束繁中 PK 1.0.1.0 正式布局剧本 `hiho` chunk 的记录边界、运行时身份、编辑器可见字段、设施目标代码和无损读取。输入必须先通过 [BEH-IMPORT-0001](BEH-IMPORT-0001-source-container-validation.md)。

本规格不为当前 EXE 无消费者的源元数据臆造玩法语义，也不要求导入器复制原版兵法对象的字符串资源缓存。

## 原作基线

`hiho` chunk 位于正式剧本数据的 `0x322`，包含 41 项，每项 38 字节，共 1558 字节。运行时兵法 ID 使用记录序号 `0..40`。

| 偏移 | 类型 | 规格字段 | 已确认语义 |
|---:|---|---|---|
| `0x00` | `u16` | `serialized_id` | 原始序号槽位；原程序读出后丢弃 |
| `0x02` | `u16` | `opaque_field_02` | 样本中等于记录序号；载入后未发现读取，设计用途未定 |
| `0x04` | `u16` | `opaque_field_04` | 样本中等于记录序号；载入后未发现读取，设计用途未定 |
| `0x06` | `u16` | `opaque_field_06` | 样本中等于记录序号；载入后未发现读取，设计用途未定 |
| `0x08` | `u16` | `system_code` | `0..8` 为九类人物熟练度系统；`9` 为无熟练度系统的空白显示值 |
| `0x0A` | `u16` | `training_requirement` | 习得熟练度 |
| `0x0C` | `u16` | `catalog_policy_value` | 目录属性键 `6/7` 的“方针”值；键 `7` 显示 `4-value`，具体规则语义未确认 |
| `0x0E` | `u16` | `opaque_field_0E` | 原始不透明槽位；未发现目录、玩法或表现读取 |
| `0x10` | `u16` | `power` | 威力 |
| `0x12` | `u16` | `catalog_grass_value` | 目录“草”列原始值；未确认战斗倍率 |
| `0x14` | `u16` | `catalog_forest_value` | 目录“森”列原始值；未确认战斗倍率 |
| `0x16` | `u16` | `catalog_earth_value` | 目录“土”列原始值；未确认战斗倍率 |
| `0x18` | `u16` | `catalog_wetland_value` | 目录“湿地”列原始值；未确认战斗倍率 |
| `0x1A` | `u16` | `catalog_water_value` | 目录“水域”列原始值；未确认战斗倍率 |
| `0x1C` | `u16` | `minimum_interval` | 冷却/CD 间隔；编辑器称“最小间隔”，目录属性键 `14` 称“休息” |
| `0x1E` | `u16` | `catalog_cost_value` | 目录“费用”列原始值；未确认实际扣费 |
| `0x20` | `u16` | `affects_facilities_code` | “对设施”代码；库存样本中 0/1 可转为复选框状态，并与当前 EXE 的硬编码设施目标集合一致 |
| `0x22` | `u16` | `compatible_array_type_mask_low` | 28 位阵形/载具类型兼容位图的低 16 位 |
| `0x24` | `u16` | `compatible_array_type_mask_high` | 同一位图的高 16 位；有效位只到 bit 27 |

`system_code` 的已知显示映射为：`0` 步兵、`1` 骑兵、`2` 弓骑、`3` 弩兵、`4` 水军、`5` 攻城、`6` 智略、`7` 谋略、`8` 策略。代码 `9` 仅见于落石和射台；原编辑器不显示系统名，运行时也不把它当作人物熟练度类别。产品可以把 `9` 技术性表示为“无熟练度系统”，但不得声称这是原作资源名称。

当前 EXE 确认 `system_code`、`training_requirement`、`power` 和 `minimum_interval` 四个数值槽进入战斗／模拟计算；此外，运行时 `+0x88..+0x8B` 会把 `+0x22/+0x24` 作为一个 28 位位图读取，以 `Array` 记录顺序 ID `0..27` 判断兵法与阵形/载具类型是否兼容，其他 UI 绘制路径据此选择显示样式。`+0x0C`、`+0x12..+0x1A` 和 `+0x1E` 另有通用目录属性读取，分别对应方针、五类地形和费用；尚无战斗／模拟消费者证据。`+0x02/+0x04/+0x06/+0x0E` 仍未发现后续读取，保持不透明。

“选择兵法”目录的三项布尔列不统一使用该位图：“陆上”固定为真；“水上”按兵法顺序 ID 与 `system_code` 派生；“对设施”直接读取 `affects_facilities_code`。其非零集合为 `6..11, 23, 25, 26, 27, 30, 31, 32`，与当前 EXE 各任务资格函数硬编码的设施目标集合完全一致。该字段是 UI 直接显示的冗余能力声明，但不是战斗资格门实际读取的权威开关。

## 重制行为

导入器必须生成 41 个按文件顺序排列的兵法定义，并暴露上述全部 19 个原始 `u16` 槽位和顺序 `Id`。`AffectsFacilities` 可以作为 `AffectsFacilitiesCode != 0` 的派生能力声明，但不能替代原始代码；战斗规则若以原作当前 EXE 为基线，应显式建模已确认的具体任务资格，而不能假定修改该源字段会改变原程序行为。导入器还必须按 `low | (high << 16)` 暴露 `CompatibleArrayTypeMask`，并允许以 `0..27` 的 `Array` 顺序 ID 查询对应位；越界 ID 返回不兼容。

已确认目录用途的七个原始字段分别暴露为 `CatalogPolicyValue`、`CatalogGrassValue`、`CatalogForestValue`、`CatalogEarthValue`、`CatalogWetlandValue`、`CatalogWaterValue` 和 `CatalogCostValue`，不再使用不透明字段名。`Catalog` 前缀限定其已确认用途；这些值不得据列名解释为战斗方针、地形倍率、移动消耗或实际扣费，也不因此加入引擎无关的玩法内容契约。两个“方针”属性共享一个原始字段，不新增第二个存储槽。

导入器不得因为库存序号副本等于记录序号而丢弃 `SerializedId`；不得根据不透明槽位的默认值推导玩法。对于 `system_code` 或其他槽位出现库存样本之外的值，必须保留原始值，不得静默归一化或拒绝整条记录。

## 状态与不变量

- 输入与前置条件：已通过 `BEH-IMPORT-0001` 的完整剧本流。
- 状态变化：无；只生成 41 个只读记录。
- 始终成立的不变量：返回顺序等于文件顺序；每项完整消费 38 字节；整个 `hiho` chunk 恰好消费 1558 字节；所有 19 个 `u16` 按 little-endian 无损保留。
- 失败行为：容器或 `hiho` chunk 尺寸不正确时抛出格式错误。
