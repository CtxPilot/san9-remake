# BEH-RENDER-0004：单份头像与统一裁剪视图

- 状态：已确认
- 日期：2026-09-10
- 实现状态：已接入，画面待用户验收
- 原版证据：[RE-SAN9PK-0035](../../research/findings/RE-SAN9PK-0035.md)

## 状态与不变量

836 张全量实验中，821 张可直接按原版锚点取景匹配 S/T，15 张需调整位置才能匹配。用户查看对照后接受这 15 张取景差异，选择统一锚点方案，避免维护独立 S/T 或另一组小图坐标。原版资源与实验搜索坐标仅保留为研究证据，不作为产品修正表。

每个头像 ID 只保存一张正常色的完整图片（原版240×240），导出至共享纹理包的 `images/portraits/`，以及归一化裁剪锚点 `(ax/240, ay/240)`。武将通过头像 ID 引用共享资源，不按武将、显示尺寸或调色板变体重复保存图片。转换器读取原版资源与锚点表，客户端只读取转换包。

## 重制行为

设原版锚点为 `(ax, ay)`，源矩形按 `(x, y, width, height)` 表达：

| 目标尺寸 | 源矩形 |
| --- | --- |
| 240×240 | (0, 0, 240, 240) |
| 160×180 | (ax, ay, 160, 180) |
| 96×120 | (ax+32, ay+30, 96, 120) |
| 64×80 | (ax+32, ay+30, 96, 120)，缩放至目标尺寸 |
| 32×40 | (ax+32, ay+30, 96, 120)，缩放至目标尺寸 |

表中坐标以原版240×240为基准。运行时将锚点、宽高和居中偏移按母图实际尺寸等比例换算，最终源矩形边界取整；高清替换图保持方形母图构图即可复用同一份相对位置。

内容契约允许同一包混用240×240、512×512、1024×1024等方形母图，每张图片独立声明实际尺寸；锚点继续以`double`保存归一化左上角，不截断小数。裁剪的左右、上下边界分别按`Math.Round`取整，因此非240整数倍分辨率的像素裁剪宽高比可有取整误差，不要求整数像素保持精确比例。界面逻辑尺寸不随母图分辨率变化；事件中作为插图展示的完整人物头像使用240×240逻辑区域，再按可用空间缩小，边框和文字布局由该逻辑区域计算。

当前仍仅导入原版240×240头像。本阶段仅准备方形母图的底层加载、裁剪和显示能力，不新增图片导入入口、编辑工具或自动识别，也不改变现有半身／面部取景规则；独立取景框后续另行设计。

所有视图共享底层纹理。两个小尺寸直接从同一母图裁剪区采样，不串联缩放，不保存额外小图裁剪坐标或逐头像修正分支。

只使用 `P_Face[0]` 导出，不保留调色板1变体。按2026-09-12用户明确要求，死亡人物实际显示时由控件shader生成灰度效果，保持Alpha；生死状态来自当前世界，不能从头像编号或图片颜色推断。同一母图可同时被正常控件和死亡控件引用，切换状态不加载另一张图片。此死亡显示规则是重制选择，不声称调色板1的原版用途已被证明。

## 验收标准

- 转换包按头像 ID 唯一保存图片，五种视图的源区域符合上表。
- 支持范围内的头像与锚点引用完整闭合；不因当前剧本可见性筛除资源。
- 512等非240整数倍母图的裁剪边界不越界；混合分辨率元数据与实际图片尺寸一致，同一母图的三种视图仅加载一份物理纹理。
- 更换人物头像母图分辨率不改变事件头像的逻辑展示区域、边框和文字位置。
- 接受原版 15 张 S/T 与统一裁剪位置的差异，不要求复原原始缩放、量化或锐化像素。
- 实际画面核对完整图、两种裁剪和两种缩图及 shader 效果；取景差异的接受不代表产品接入已经通过画面验收。

## 正式版 Mod 支持规划

用户补充的兼容需求：部分原版 Mod 定制了 L/S/T 三种尺寸头像，却未同步更新偏移文件。接入正式版 Mod 导入时，应考虑利用同 ID 的中、小头像与大图进行图像匹配，推导适合该头像的裁剪位置，而不能默认沿用的偏移文件仍适合新画面。

推导属于导入阶段，结果转换为统一头像元数据，客户端继续使用单份母图。此项不改变当前原版样本的统一锚点方案，也不引入那 15 张原版头像的修正表。匹配方法、可信度判定及无法匹配时的处理方式，在实现 Mod 支持时另行明确；不得把未验证的推导结果视为原版锚点事实。

## 未决问题

当前原版样本方案无阻塞项。正式版 Mod 的裁剪推导仍属上述后续规划，不作为当前接入的验收条件。
