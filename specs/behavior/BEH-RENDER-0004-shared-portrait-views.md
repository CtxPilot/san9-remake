## 状态与不变量

836 张全量实验中，821 张可直接按原版锚点取景匹配 S/T，15 张需调整位置才能匹配。用户查看对照后接受这 15 张取景差异，当时选择统一锚点方案。2026-11-06用户确认分离半身与面部锚点；初始坐标继续保持此前画面，不导入逐头像修正表。原版资源与实验搜索坐标仅保留为研究证据，不作为产品修正表。

每个头像 ID 只保存一张正常色的完整图片（原版240×240），导出至共享纹理包的 `images/portraits/`，以及独立的归一化半身锚点`BustAnchor`和面部锚点`FaceAnchor`。武将通过头像 ID 引用共享资源，不按武将、显示尺寸或调色板变体重复保存图片。转换器读取原版资源与锚点表，客户端只读取转换包。

## 重制行为

以240×240母图说明，半身左上角为`(bx, by)`，面部左上角为`(fx, fy)`；源矩形按`(x, y, width, height)`表达：

| 目标尺寸 | 源矩形 |
| --- | --- |
| 240×240 | (0, 0, 240, 240) |
| 160×180 | (bx, by, 160, 180) |
| 96×120 | (fx, fy, 96, 120) |
| 64×80 | (fx, fy, 96, 120)，缩放至目标尺寸 |
| 32×40 | (fx, fy, 96, 120)，缩放至目标尺寸 |

表中坐标以原版240×240为基准。运行时将两个锚点与固定宽高比例按母图实际尺寸换算，最终源矩形边界取整；高清替换图保持方形母图构图即可复用同一份相对位置。

内容契约允许同一包混用240×240、512×512、1024×1024等方形母图，每张图片独立声明实际尺寸；锚点继续以`double`保存归一化左上角，不截断小数。裁剪的左右、上下边界分别按`Math.Round`取整，因此非240整数倍分辨率的像素裁剪宽高比可有取整误差，不要求整数像素保持精确比例。界面逻辑尺寸不随母图分辨率变化；事件中作为插图展示的完整人物头像使用240×240逻辑区域，再按可用空间缩小，边框和文字布局由该逻辑区域计算。

原版转换仍只生产240×240头像；半身锚点取原始偏移`(ax/240, ay/240)`，面部锚点取`((ax+32)/240, (ay+30)/240)`，保持分离前的画面。用户头像通过下述编辑页新增。两个框支持独立或联动平移，半身宽高占母图`2/3、3/4`，面部占`2/5、1/2`，暂不独立缩放。

所有视图共享底层纹理。两个小尺寸直接从同一母图裁剪区采样，不串联缩放，不保存额外小图裁剪坐标或逐头像修正分支。

只使用 `P_Face[0]` 导出，不保留调色板1变体。按2026-09-12用户明确要求，死亡人物实际显示时由控件shader生成灰度效果，保持Alpha；生死状态来自当前世界，不能从头像编号或图片颜色推断。同一母图可同时被正常控件和死亡控件引用，切换状态不加载另一张图片。此死亡显示规则是重制选择，不声称调色板1的原版用途已被证明。

## 验收标准

- 转换包按头像 ID 唯一保存图片，五种视图的源区域符合上表。
- 支持范围内的头像与锚点引用完整闭合；不因当前剧本可见性筛除资源。
- 512等非240整数倍母图的裁剪边界不越界；混合分辨率元数据与实际图片尺寸一致，同一母图的三种视图仅加载一份物理纹理。
- 更换人物头像母图分辨率不改变事件头像的逻辑展示区域、边框和文字位置。
- 接受原版 15 张 S/T 与统一裁剪位置的差异，不要求复原原始缩放、量化或锐化像素。
- 实际画面核对完整图、两种裁剪和两种缩图及 shader 效果；取景差异的接受不代表产品接入已经通过画面验收。

## 头像编辑器与用户包

标题菜单“编辑头像”的画框图标位于内容编辑器图标右侧，直接打开头像编辑器；头像编辑器只保留此独立入口，不再从游戏资料编辑器进入。使用者从已保存的共享武将和新武将中建立索引。提供图片名／使用者两列的头像列表、按图片名或使用者搜索、未保存筛选、图片新增、修改自建头像名称、独立锚点编辑、撤销／重做、恢复打开时及基础取景。画布叠加半身与面部框，两框独立保存位置；主画布显示完整母图，右侧只提供半身和面部两种取景预览，不重复展示完整图，也不另列64×80或32×40预览。“自动面部取景”放在工具栏首位，面部／半身使用并排可分别选中的按钮，至少选中一种；单选独立调整，双选时拖动、方向键（Shift为10像素）及母图像素坐标输入共同平移两框，保持整数像素起点的相对位置，以两框共同可用边界限制位移，一次联动可整体撤销；点击取景框切换坐标参考对象，保留双选状态；所有编辑均转换为归一化锚点；画布缩放／平移不改变数据，取消拖动、切换对象或失焦恢复本次拖动起点。常用取景操作集中在画布上方，恢复与推算半身收进“更多”菜单，操作说明按需打开；像素坐标保留在画布下方，归一化值放入坐标悬停提示，引用信息以单行摘要显示。

新增图片必须是至少16×16的方形母图，不自动裁切或拉伸；导入时默认保留原图尺寸，也可指定16～16384像素的整数边长（初始建议512），以Lanczos等比缩放整张母图后转为标准PNG草稿，不改动源文件。客户端解码PNG／JPEG／WebP，转为不透明RGB。支持一次多选图片，尺寸设置统一应用于本批，保留原图尺寸时每张独立使用其原尺寸。依次创建草稿并执行与工具栏相同的自动面部取景及公式半身推算，按实际保存尺寸吸附整数像素；读取或校验失败只跳过当前文件，检测失败保留已导入图片及默认取景。多人脸不自动选人，保留默认取景，在结果中提示玩家选择对应头像后重新点击自动取景并点选候选。导入选项“同名覆盖”默认关闭；开启后按去扩展名、去首尾空白且忽略大小写的文件名匹配左侧图片名（包括固有头像编号与自建头像名称），唯一同名时替换图片并保留身份、名称和人物引用，无同名时新增，多个同名目标时跳过并报告。同批后续同名文件覆盖该批较早导入的同名头像；固有头像同名时在玩家包中替换图片，例如`0.png`匹配图片名`0`，不改动基础转换资源；固有与自建头像之间同名也视为多个目标。匹配索引每批建立一次，成功新增后增补索引。进度窗口可停止，当前已加入草稿的图片保留；完成或停止后汇总已导入数量、失败和需手动处理项。批次期间禁止保存和重复导入，关闭请求先停止批次，结果不自动保存。手动触发的单图识别仍在切换、手动编辑或保存时取消，不覆盖后续操作。图片字节先保留在内存草稿，保存时复制至`<用户数据目录>/portrait-packs/my-portraits/images/<图片版本标识>.png`，不依赖导入源路径。`portraits.json`使用独立schema2，持有包ID、新头像名称／稳定标识／图片描述／两个锚点，以及按基础头像键指定的覆盖；覆盖的可选`Image`为空时仅覆盖锚点，非空时替换母图。该可选能力沿用schema2，不要求现有头像包迁移。不覆写原版转换包，不复制基础图片，不随人物或战局存档保存图片。

像素坐标输入只显示整数，步长为1。新导入默认取景、拖动、方向键、数值输入、自动定位及半身推算均吸附到母图整数像素，归一化元数据仍以double保存；自动定位先吸附面部位置，再推算并吸附半身。固定比例框在母图边缘存在非整数上限时向内吸附，避免越界。已有元数据打开时只按实际裁剪的整数起点显示，不因显示精度改变而自动改写；恢复仍保留对应基准值。

自建头像名称默认取导入文件名（去扩展名），可在头像页顶部直接编辑，回车或离开输入框时提交到草稿；空名称恢复原值，允许同名。改名进入现有草稿、撤销／重做及保存流程。武将和新武将共用的头像选择器直接显示并按名称搜索自建头像，武将编辑表单的已选头像下方也显示名称；不再统一标为“自建头像”或要求玩家辨认内部随机标识。名称仍保存在用户包原有的`Name`字段，运行时投影到只读显示资料，不改变schema、图片路径或人物头像引用。

新增头像引用为`user/<包ID>/<头像ID>`，人物资料继续只保存`PortraitKey`。运行时合并基础头像与用户包，再验证资源引用；新增头像的数字序号仅为当前加载中的显示顺序，不是持久身份，也不依赖原版数量或编号区间。包内图片路径受包根约束，解析后通过运行时来源表加载；缺图、缺少覆盖目标或损坏包明确失败，不静默忽略。

保存先校验整包、发布新增图片，再原子替换清单；新增与替换图片均使用独立文件路径，不覆写旧文件。清单失败只清理本次新增文件，保留原图与草稿供重试。外部修改清单时拒绝覆盖。保存成功更新共享头像服务，后续打开的头像选择和预览立即可用；已打开控件／对局不热更新，重新加载后应用。保存会清空撤销历史，防止撤销新增操作移除已经发布并可能被人物引用的头像。“恢复打开时”还原当前头像的图片、名称与取景，本次新增头像还原导入时的图片、名称与默认取景；“恢复基础取景”只还原取景，不改图片或名称。

使用者摘要来自打开头像页时读取的已保存共享武将和新武将库，不宣称覆盖独立剧本私有人物。“更多”提供单张替换图片、自建头像删除及固有头像恢复原版：

- 固有与自建头像均可替换方形母图，沿用导入的保存尺寸选项并重新自动取景。保留头像键、运行时序号、自建名称和武将引用；固有头像只在玩家包中覆盖图片，不覆写基础转换资源。
- 固有头像禁止删除；“恢复原版”移除该头像的图片与锚点覆盖，完整恢复基础母图和两种取景，可撤销。
- 只允许删除没有使用者的自建头像，确认前与确认时核对已保存共享武将、新武将，保存含删除的草稿时再次读取磁盘引用；仍被使用或无法核对时拒绝发布，不清除人物引用。
- 替换、删除与恢复均进入草稿和撤销历史，保存后生效。打开时的图片和本次新建基准保留至页面关闭，支持保存后恢复；关闭时先核对磁盘清单与最后保存快照相同，只清理本会话已知且最后保存清单不再引用的图片，不遍历删除包内其他文件。外部清单变化时跳过清理。

同名覆盖支持批量替换，暂不提供逐一指定目标的批量替换或批量删除、多个包管理、分享导入导出或独立可缩放取景。

验收包括新增图与锚点保存重开、引用键稳定、游戏加载与人物选择共用资源、恢复／撤销草稿隔离、保存失败清理和外部修改保护。自动验证不代替实际画面与操作体验验收。

## 面部自动取景

“自动面部取景”直接使用`Cdd.FaceDetection 0.1.0-preview.4`的托管实例API，不启动Python或检测子进程。按实际来源解码原版、自建已保存或未保存草稿图片，RGB分析图统一为240×240（仅分析，不修改母图），坐标归一化回母图；不从GPU回读、不改变母图。页面持有串行后台检测器，复用实例工作区，关闭后释放。检测结果、像素和候选不写入头像包或游戏存档。

候选分数至少0.8且坐标有效才参与取景；分数为模型评分，不是构图质量或校准概率。一个候选直接应用，多个候选在画布显示绿色框并由用户点选；无可靠候选／读取失败保持原草稿。切换头像、开始手调、撤销／恢复、保存或关闭使旧请求及候选失效；已进入同步推理的工作可结束，但迟到结果不得写回。

面部构图采用实验分支第二、四、五轮结论，使用双眼中点、鼻尖和嘴角中点，而非仅按眼线居中。以下公式均在240单位的分析坐标中计算，最后转换为独立归一化锚点；更换母图分辨率不改变规则。

- 横向：以`eyeX + b0 + b1×(noseX-eyeX) + b2×(mouthX-eyeX) - 80`计算半身基准X，夹至0..80并四舍六入五成双取整；再加32得到面部X。根据检测脸框左右各6单位留白，在面部X范围32..112内作最小调整；区间冲突时保留姿态拟合值并标记受限。
- 纵向：压缩构图眼线偏移为`90.50020106678383 + 0.9210757121211361×(noseY-eyeY) - 1.7537340016555039×(mouthY-eyeY)`。嘴眼纵距在30..34之间用smoothstep平滑过渡到普通构图偏移42；按上方6、下方4单位保护检测框。无可行区间时沿用实验第三轮的基线／单向上移结果，不套用另一套居中公式。该回退使用基线眼线偏移51.5。
- 自动构图沿用实验的面部X范围32..112、Y范围30..90，以保持半身公式推算时的居中关系；这不是手动编辑的限制。两个独立锚点仍允许各自移动至母图全部合法区域。

纵向三项系数直接保留于实验分支`evaluate_balanced.py`。缺失的横向系数及基线偏移按原实验方法重新恢复：当前`preview.4`检测836张原版母图，仅418张偶数ID、评分至少80的观测参与校准；Huber IRLS delta5、30轮，奇数ID不参与拟合。横向拟合特征为`[1, noseX-eyeX, mouthX-eyeX]`，目标为`原始半身X+80-eyeX`；系数为`[-0.32687782474704924, -2.2626836645913575, 1.1150760182899369]`。基线眼线偏移取同一校准集`eyeY-原始半身Y-30`的中位数51.5。运行时只使用全局系数，不读取实验图片、结果表或头像编号。

2026-11-07核对：836张均有检测结果；835张达到产品评分与坐标要求，C#产品算法的取景像素及受限标记与实验Python计算全部一致。头像0从简化算法的`(86,54)`修正为`(76,39)`，原始参考为`(71,34)`；不要求逐张等于原版。奇数对照集对原始锚点的距离中位数约5.05单位、P90约10.05单位，距离不是构图质量分数，也不是原版S小图反推坐标的比较。检测框之外的头饰、发髻和胡须仍需画面核对。

校准脚本、临时验证工程、原始观测、报告及专用Python环境已清理；只保留上述公式、全局系数、校准方法和验证结论。产品不依赖这些过程产物，启动或编辑页面时不重新拟合。

自动应用同时按公式`BustAnchor=clamp(FaceAnchor-(32/240,30/240))`推算半身，两项一起构成一次可撤销草稿变更。手调面部后不会自动重算半身，另可在“更多”菜单选择“由面部推算半身”只更新半身。此规则没有肩膀检测或半身拟合；两种取景的后续手动修改相互独立。

## 格式升级

纹理包schema7、用户头像包schema2只读取独立锚点格式，不在运行时兼容旧单锚点。旧包通过显式命令升级，复制原单锚点为半身锚点并加既定偏移生成面部锚点；图片路径、图片文件和原有取景保持不变。命令只接受前一版本，格式或锚点非法时不发布，发布前检查源文件未被外部修改。无需重转纹理、世界或开局内容；新生成包由转换器直接输出两个锚点。

```powershell
dotnet run --project src/San9.Tools -- upgrade-portrait-anchors --texture-package local/generated/content/shared/textures
dotnet run --project src/San9.Tools -- upgrade-portrait-anchors --portrait-pack "<用户数据目录>/portrait-packs/my-portraits"
```

## 后续取景尺寸与新世代半身大图

后续考虑开放半身、面部两种取景的相对尺寸，分别调整各自取景区域占母图的大小，仍固定半身8:9、面部4:5的宽高比。位置与尺寸分别由各自视图持有，小头像继续共用面部取景；调整取景大小不改变界面显示区域的逻辑尺寸，也不改写母图。此操作与仅改变观察大小的画布缩放分开。

该规划已考虑支持新世代半身大图：面对不同人物占比及更完整的半身构图，可通过独立调整面部与半身的取景大小适配，而不要求作者预先裁成原版构图。届时同步评估非方形母图、自动取景的尺寸估计，以及半身公式推算对可变取景尺寸的适配；不把本轮固定尺寸公式直接延伸为可变尺寸规则。

本轮仍只实现独立锚点、固定相对尺寸及面部自动定位；上述尺寸编辑与扩展资源接入属于后续规划，尚未实施。

## 正式版 Mod 支持规划

用户补充的兼容需求：部分原版 Mod 定制了 L/S/T 三种尺寸头像，却未同步更新偏移文件。接入正式版 Mod 导入时，应考虑利用同 ID 的中、小头像与大图进行图像匹配，推导适合该头像的裁剪位置，而不能默认沿用的偏移文件仍适合新画面。

推导属于导入阶段，结果转换为统一头像元数据，客户端继续使用单份母图。此项不改变当前原版样本的初始取景位置，也不引入那 15 张原版头像的修正表。匹配方法、可信度判定及无法匹配时的处理方式，在实现 Mod 支持时另行明确；不得把未验证的推导结果视为原版锚点事实。

## 未决问题

当前原版样本方案无阻塞项。正式版 Mod 的裁剪推导仍属上述后续规划，不作为当前接入的验收条件。
