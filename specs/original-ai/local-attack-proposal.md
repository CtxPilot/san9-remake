## 1. 问题与目标

[白马港研究](../../research/topics/ai/military.md#baima-idle-20261029)已经证明：白马兵力、人物、士气及钱粮合格；邺批次先选濮阳，从白马寻路遇到官渡后改攻官渡，随后按官渡属城及其军事邻城重建来源，白马被排除。问题是发现目标与收集来源使用不同的关系，不是需要为白马降低兵力门。

设计基线使用这条链：`Attack → AttackTargetAlongRoute → AttackSources`。B20此前保留的后续目标尝试能避免一个失败目标终止整批，但不能恢复被地理筛选遗漏的来源；v245已替换该链。增加邺—洛阳特例连接只证明阻断点，不能作为产品修复。

目标行为：有合法近处攻击机会时，港口、关和城市都能按自己的实际位置成为来源；来源与目标的属城关系不能否定已成立的进攻通路。同时抑制跨越前线、绕远攻打普通敌设施。保留 original AI 的战略偏好、工作调度、留兵、强度判断和单队编成，使变化能单独解释、比较和验收。

## 3. 核心模型：同一份有向进攻关系

通用底层采用[据点交通网络设计](transport-network-design.md)：统一设施节点，开局完成60日参考关系、参考行程、水陆代价和途经摘要，几何变化整体重建，局部维护尚待比较。工作9在其上建立派生查询，回答“当前来源的网内目标中，哪些通过当前进攻资格”。交通网不包含兵力及敌我资格；源—目标关系先受交通网约束，再由参考路径换算、动态设施判断及来源资格收窄。

建立关系的顺序：

1. 据点身份来自当前有效世界对象。几何查询保留没有兵或人物的据点作为目标／障碍；可出兵来源另按现有 `WorkSources`、所属军团、士气和人物规则筛选，不把所属城市当作来源位置。
2. 从来源的交通网出边取候选；无边不考虑，不以真实阵形更快、目标明确或同属城为由补查，不通过中间设施多跳扩展。
3. 读取已完成交通边摘要，换算基础编成行程，用当前敌我及施工状态解释途经设施和地域；慢地形及工程标记供兵法／阵形选择复用。参考路径不能由基础编成使用或被中间敌设施阻断时，才查询该网内目标的公共替代路线。
4. 只有参考或替代路线没有必须先处理的其他敌建筑、行程在策略上限内，才建立可用进攻关系。最终编成继续检查现有公共连通性、实际出发位置和粗格行程；公共查询未完成不缓存为不可达。
5. 目标来源查询使用同一有向关系，不再另用目标属城、军事邻城和地域邻接的三表并集重建。

不变量：只要 `source → target` 在当前输入下成立且来源资格仍有效，目标的来源表就必须包含该来源。路线发现与来源收集互为同一关系的两个查询方向，不设置“沿路起点额外放行”的补丁分支。

**沿路改目标的处理（v250修正）。**高优先级目标参考路线上的首个满足战略目标资格的途经据点承接原目标阶段，包含城市及中立据点，不含工程障碍类，不额外要求前沿接壤。候选先在同一来源的交通网中确认直接边，随后仍按统一交通关系收集来源，避免恢复白马被目标属城过滤的问题。普通已占领敌设施独立候选阶段仍要求前沿接壤。实际来源不足、路线或兵力不合格时，继续后续目标，按改选后的实际目标去重。

v245～v248把前置敌设施仅作为独立普通设施候选，造成其不再承接城市阶段优先级；v249部分恢复，v250去掉额外的种类、归属及前沿限制。交通网仍限定候选范围，实际目标必须有来源到该据点的直接参考边。沿路施工冲突只检查本批选定主路线，不扩展为每个额外来源的资格门。转建设使用改选后实际来源—目标关系的途经地域，建设来源独立从同城士气合格且至少有两名空闲人物的据点中按兵量重选。v251恢复已有兵力分配后尝试完即结束当前城市批次的规则，命令全部为空或被拒绝也不继续后备目标；前置资格不合格或分配为空仍可继续。失败后继续后备可能合理、有助减少空转，但属于独立执行策略调整，本轮暂不采用。

## 4. 目标资格与距离建议

建议首轮使用以下统一约束，不再把“放宽来源”和“再增加远征例外”交替叠加：

| 情况 | 建议规则 |
| --- | --- |
| 所有工作9的实际出兵来源 | 来源到目标必须有交通网直接边；网内实际粗格估计行程≤60日，同属城和明确战略目标也检查 |
| 普通已占领敌设施候选 | 另须其地域与至少一个己方有效据点地域接壤；保持现行战略敌对资格 |
| 城市、指定目标及未占领设施后备 | 保留各自目标阶段和敌对／无主规则，不将伴侣普通敌设施接壤门推广到所有阶段；仍检查上述行程 |
| 仅地域接壤，但网内公共路线不可达、存在途中敌设施或出发位置不可用 | 不出兵；粗格估计不保证全部细步通行 |
| 普通敌设施虽然60日内可达，但与己方地域不接壤 | 不进入普通敌设施阶段，不能仅因兵少获得机会 |

接壤表示目标地域与己方有效据点所在地域的拓扑关系，不等于源据点必须亲自接壤，也不要求该己方据点属于当前军团；实际调兵仍只取当前军团合法来源。工作9的实际来源—目标资格不再依赖军事邻城表。

60日参考范围按用户指定实施，用白马、网外目标与网内慢阵形成对核对；不得给白马、特定城对、明确目标或异民族添加网外旁路。该范围不证明全图战略质量，后续调整须另有依据。

## 5. 部队索引怎样服务 original AI

实验分支 `MilitaryForceIndex` 值得借鉴的是“物理事实、空间候选与策略含义分离”。其中物理索引不含命令，目标反向关联另在观察层建立；不能把整个索引当作已经算好的威胁。

本次只需两层派生数据：

- **对象与兵力索引**：据点／部队类型化身份、所属势力／军团、当前位置／占地、现兵和伤兵。内嵌守军不作为第二份野外兵力；伤兵不进入现有即时战力。先一次扫描建表，不默认移植空间桶、势力局部替换和全增量更新。
- **命令关联索引**：按目标索引现有原始／有效命令，另按需缓存 `ProjectedOrder` 的障碍投影。沿用B28可读取有效命令的范围，不引入实验分支的信息发布时点或新权限。`FieldUnit`、`Active`、每日执行历史及同盟／履约关系仍由具体消费者过滤。

初期用于查询工作9的目标防守、来源压力、已有友军进攻与建设冲突，保持 `Defense`、`Reserve`、`Strength` 的现有算式，包括薄弱来源的负贡献及原有强度特判。不因改用索引就把附近全部驻兵相加、不以实际批次兵量替换原强度门、不新增战场推演。

`ProjectedOrder` 只对现有语义需要的候选按需寻路；建立物理索引时不为全世界每个部队计算一次投影。其他工作可继续使用原查询，后续有独立收益再迁移。

## 6. 接入与提交边界

`OriginalAiMilitary.Attack` 保留按城市兵量排序的批次调度，以及指定目标、指定势力城市、其他城市、无主城市和设施的既有优先级。候选改从当前批次来源的出边并集取得；选中目标后，从同军团合法来源的入边收集兵力，继续使用现有 `Strength → Allocate → AttackPeople → Deployment → Send`。

城市分组只决定哪个批次先评估；同一来源允许按既有额度派多队，跨批次是否仍可出兵由当前兵将与留守决定。候选重复消除限定在当前批次及当前输入，不能在一个失败来源之后永久标记目标已处理；也不增加每个来源一旬只能出一队的限制。

基础阵形关系只是粗筛。实际人员、阵形、船型、兵量和占地确定后，须按完整候选重新检查行程、路线和公共出征资格，再提交同一份公共准备结果。实际选阵变慢而超出上限时不提交该队；本工作内对同一完整载荷记忆确定失败并继续其他候选，不重抽完全相同失败计划直到尝试耗尽。失败不扣兵、不占人物、不计入已派遣量。

粗格 `Estimate` 不能保证真实宽度通行或每日到达。按用户决定，普通进攻不在出兵前执行逐日细步预演；最终候选保留真实编成的出发位置、粗格行程和途中敌设施检查。时间门使用冻结当前占位下的行程估计，实际细步间隙及之后变化的阻挡由正常每日推进处理，不承诺未来第60日必然到达。

本轮只修改工作9的候选与来源关系，保留顺序编队和实际提交反馈。工作59履约、51输送、57撤回及58迎敌／救援不自动切换策略；尤其不为尚未需要的第二队提前抽取人物和兵法。若公共查询抽取影响这些消费者，只验证等价性，不顺带改变其规则。

## 7. 生命周期与实现规模

| 层次 | 所有权和实现建议 |
| --- | --- |
| 地图、占地、移动条件和路线时间 | Core既有公共规则；若需单源多目标算法，在Core独立实现与验证 |
| 本工作图、来源／目标关系、命令索引与候选顺序 | Application派生查询，不写入世界、不保存、不消费正式随机 |
| 缓存 | 限定本控制事务／军事工作，按实际依赖复用；命中与冷建结果相同 |
| 提交与资源 | 沿用现有公共命令准备、验证、事务发布与反馈 |

据点几何、建拆、所有权或外交变化使相关进攻关系失效；部队变化使占位路线和命令关联失效；人物／任务、兵量、士气与军团变化使来源资格重评。账户变化重核费用，不单独使静态地形失效。拆障可能打开旧路线以外的捷径，不能只检查旧路线经过的对象。

首轮复用当前 `MilitaryRouteQueryContext` 和按需源—目标结果缓存，先建立能与直接查询对照的稀疏关系，不复制实验分支整套查询预算、观察、账本、战役状态或存档协议。实验分支 `MilitaryTransportNetwork/BattlefieldTravelField` 的有界单源多目标搜索仅在重复搜索确有成本时独立移植；其端点、粗格占地和时间优化口径须与主线公共导航核对，不能将实验类原样视为可替换实现。

所有候选按稳定内容顺序及既有排序决胜，哈希表只作索引。诊断输出来源、实际目标、估计行程、前沿资格及淘汰阶段；未完成另记，不用墙钟决定选择。不建立持久搜索游标或新的命令／保存结构。

## 8. 最小验收与交付顺序

先用公开自制局面固定下列行为，再接生产工作9；私有白马存档只作补充对照，不能成为唯一回归或提交产物。

| 样例 | 应观察的结果 |
| --- | --- |
| 白马式港口有兵有人、近敌港与其地域接壤，但双方属城不在军事邻城表 | 无需修改城图，公共入口实际接受从该港攻击近敌港的命令 |
| 原意攻城市的通路被近敌港挡住 | 近敌港作为独立实际目标存在，其来源包含起始港；未清障时不虚报穿过敌港的直攻关系 |
| 敌港转为己方 | 当前近敌机会重新发现；不会固定依赖“沿路碰到官渡”才能出兵 |
| 设施接壤但实际路线绕远超过上限；同属城也如此 | 不出兵；接壤和行政归属都不能绕过时间门 |
| 普通敌设施不接壤，但可达、兵少 | 不进入普通设施机会阶段；指定目标与无主后备按各自规则测试 |
| 近处隔水无合法船型、实际出发占位受阻 | 粗候选不等于实际接受命令；失败后继续其他合法候选 |
| 网外目标在快速实际阵形下可达，或被指定为战略目标 | 不进入普通进攻候选，不为它补查路线 |
| 网内目标粗格可达，但实际宽队可能卡在后续窄口 | 不增加出兵前逐日预演；可按公共资格出兵，实际通行由每日导航处理 |
| 一个来源不可用、另一个来源可用；高优先目标失败、后备合法 | 继续来源／目标评估，不因首项失败遗漏其余机会 |
| 留兵不足、人物耗尽、钱粮不足、公共准备或提交拒绝 | 保留现有强度及留守语义，拒绝没有资源／随机的部分发布 |
| 首队已占用兵将，来源仍能合法派第二队 | 每队读当前输入，保持多队能力；累计投入仅计实际成功提交 |
