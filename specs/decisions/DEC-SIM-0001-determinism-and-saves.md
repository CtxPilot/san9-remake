# DEC-SIM-0001：确定性结算与显式保存边界

- 状态：已确认
- 日期：2026-08-15；后续选择见替代关系。
- 行为：[会话保存](../behavior/BEH-SAVE-0001-session-persistence-replay-and-headless.md)、[随机与SL](../behavior/BEH-SIMULATION-0002-randomness.md)、[时间推进](../behavior/BEH-SIMULATION-0001-time-progression-and-state-visibility.md)。

## 背景与选择

旬制推进、自动对局及跨平台恢复要求相同初态、命令顺序和随机状态得到相同结果。采用类型化公共命令、显式稳定提交顺序和项目自有随机算法；显示只消费已提交事实，不能决定规则结果。

保留即时效果与持续任务的各自生效时机，不把全部命令拖到共同旬边界。这样复用原作已确认时序和现有任务模型，代价是先后手可观察到不同即时状态；将来联机设计须重新审视，当前不因此建立平行状态。证据见[RE-0123](../../research/findings/RE-SAN9PK-0123.md#命令生效时机复核2026-09-06)。

玩家存档保存必要当前状态，完整诊断由显式调用提供，不累计全局操作／事件历史、不用完整性哈希替代状态校验。这个选择避免存档随操作数线性增长，代价是旧序号只表示已处理，不逐条核对过去载荷。结构、引用、稳定边界和命令水位仍严格校验。

玩家读档与精确恢复具有不同随机语义，以满足SL体验和确定性复现；已经确定的任务结果不重抽。具体分类、边界和验收只在对应BEH维护，不在本决策复制流表、序列化字段或CLI参数。

## 备选与代价

| 未采用方案 | 原因／代价 |
| --- | --- |
| 各系统直接改显示节点或使用平台随机 | 逻辑顺序、规则所有权和跨版本序列不可保证 |
| 全部命令旬末统一结算 | 改变即时命令及任务先后语义，当前没有足够产品理由 |
| 任意待答步骤可存档 | 引入日内游标、提案及半事务恢复协议；当前只支持稳定下令和已完成终局，未来逐日保存另定完整日边界 |
| 尽力兼容旧结构或按内容指纹拒绝 | 前者掩盖语义缺失，后者妨碍合法内容修改；未知格式拒绝，规则版本差异告警后按当前规则运行 |

- 2026-09-19：稳定边界替代待答保存，保存中的持续任务继续保留。
- 2026-10-11：规则版本不同改为警告，结构版本仍严格读取，不提供隐式迁移。
- 2026-10-13：移除内容指纹门槛、默认快照哈希和重复流指纹；诊断比较实际语义。
- 2026-10-22：录像需求不足以支撑维护成本，撤下录制／导出／播放和专属协议，不保留空框架。此前调试录像及玩家回放计划均被此决定替代；普通存档、精确恢复和显式命令脚本继续维护。
